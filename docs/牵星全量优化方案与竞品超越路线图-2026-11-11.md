# 牵星全量优化方案与竞品超越路线图

日期：2026-11-11
适用范围：研究、回测、Paper、实盘交易、数据、可视化、观测、发行和运维
状态：实施计划；文中的性能目标是待测目标，不是当前实测结论。

本文将现有架构方案、数字资产实盘审计、能力目录与最新代码变化合并为一份可执行路线图。它不替代各模块设计文档；实施时以代码、版本化协议、能力矩阵和验收证据为准。

## 1. 目标与原则

目标是让用户从安装到“取真实历史数据、选择常见策略、运行可信回测、查看交互结果、切到 Paper、按交易所能力进入 Demo”有一条短而可靠的路径；同时让专业用户获得高吞吐、可复算、多账户隔离、可追踪和可恢复的工程能力。

“超越竞品”按各类可量化能力分别验证，不用一句总评掩盖取舍：

- **执行效率：** 对同输入、同撮合语义、同硬件和同结果正确性，测回测吞吐、批量参数实验耗时、数据导入速度、峰值内存和实时信号到提交的本地耗时。
- **核心流程：** 安装、取数、策略选择、回测、诊断、报告、Paper、Demo 各阶段有贯通入口和可恢复状态；步骤失败时定位到具体数据、参数、账户、订单或运行 ID。
- **易用性：** 新用户可以一条 quickstart 得到可视化报告；从样例数据切换到真实数据、从回测切换到 Paper、从 Paper 切换到 Demo 都能明确看到新增前置条件。
- **可视化：** 回测、策略比较、数据质量、订单生命周期、账户持仓和运行健康共用同一套可核对的事实模型。
- **可观性：** 每个运行、策略、账户、交易所、订单组、订单和成交可通过稳定 ID 串起日志、指标、事件与报告；故障可从 Unknown/部分成交继续对账。

安全与事实原则：无凭据不访问私有接口；没有交易所证据不标为已验收；没有 OOS 证据不称策略有效；本地模拟不称实盘成交；不支持的订单形态必须在提交前拒绝。

## 4. 目标架构和核心对象

### 4.1 一条研究链、一条交易链

```text
研究：数据源 → 校验/冻结 → 策略与参数 → 回测/搜索/OOS → 结果身份 → 报告/比较/复算

交易：策略意图 → 能力/单位/规则检查 → 账户预留与风控 → OMS/幂等提交
     → 交易所原始回报 → 订单组/子订单归约 → 账本 → 对账/恢复 → 操作台
```

两条链共享 Instrument、费用/成本模型、策略意图、运行 ID 和报告事实；订单提交不能绕过 Runtime/Risk/OMS 直接从 Python worker 调交易所。

### 4.2 版本化的领域订单意图

扩展领域订单模型，不把交易所私有参数字典作为稳定 API：

1. **基础单：** Market、Limit、PostOnly、IOC、FOK；显式价格/数量单位、有效期和 client ID。
2. **条件单：** Trigger、StopLoss、TakeProfit；触发价、触发价来源（last/mark/index）、触发后执行方式（market/limit）、执行限价。
3. **追踪单：** activation price/type、callback ratio/spread、触发后执行方式；精度和范围受市场能力规则约束。
4. **保护组：** 订单附属止损/止盈、持仓保护组、独立 OCO 两腿组。记录 group ID、parent/child IDs、数量来源、部分成交后的保护数量和一腿成交时另一腿的原子取消语义。
5. **改单/撤单：** 新总量与已成交累计量的语义明确；区分 native amend、cancel-replace 与普通 cancel/new。不能把撤单重挂称为原子改单。

新增 `OrderGroup` / `OrderLeg` 生命周期事实：创建意图、提交中、部分受理、活动、部分成交、一腿触发、对端取消中、终结、Unknown/需对账。进程超时后的提交结果、改单结果和 OCO 对端取消结果均进入对账，禁止盲目重发。

精度和数量必须在领域边界带单位：BaseQty、ContractQty、QuoteBudget；Money/fee 带币种；价格、触发价格和比例明确 scale/rounding。兼容旧 raw schema，新增字段进入新的 schema/hash 版本，并提供旧产物只读解析与迁移工具。

### 4.3 Venue Capability Profile

能力键至少由 `venue × product × account_model × position_mode × order_intent × operation` 组成。能力状态分 `implemented`、`code_tested`、`packaged`、`sandbox_tested`、`production_approved`。静态矩阵、CCXT 能力表和市场规则快照共同门控运行；只有具备对应成熟度证据才对 UI 显示可用。

## 5. 交易所实现方案

交易所适配保持窄端口：行情/规则、账户查询、订单提交、订单组/改单/撤单、回报和对账各自独立；CCXT 是一条适配路径，不覆盖供应商账户模式差异。

| Venue / 产品 | 规则与领域映射重点 | 实施顺序 |
|---|---|---|
| OKX Spot / Swap | 每笔普通单传正确 `tdMode`；Hedge 使用 `posSide`；合约量以 contracts；附加 `attachAlgoOrds` 与独立 `/trade/order-algo` 区分；独立 algo 的查询、撤销、修改及 child IDs 要进同一订单组。保护单仅在父单成交时激活等状态事实要保存。 | Spot 普通单 → Swap OneWay/Hedge → parent-attached TP/SL → independent algo/OCO/trailing → amend/recovery |
| Binance Spot | OCO 是 order-list 资源而非普通单；保存 orderListId 和两个 order IDs，成交后核对另一腿取消。普通 amend 与 cancel-replace 是不同操作，明确 `cancelReplaceMode` 语义。完整读取过滤器及账户级限制。 | 过滤器补齐 → Spot OCO/order list → cancel-replace → user stream 恢复 |
| Binance USDⓈ-M / COIN-M | 普通单与 conditional/algo 单区分；核对当前 API 的 New Algo Order/Modify/Cancel Algo Order；Hedge 的 `positionSide` 与 `reduceOnly` 互斥限制；不同产品条件单规则及 trailing activation/callback 范围独立登记。 | USDⓈ-M OneWay → Hedge → algo stop/TP/trailing → amend/cancel/reconcile → COIN-M 单独验收 |
| Bitget Classic | 合约开平按 `side + tradeSide`；保证金/币种字段使用 Classic 契约；追踪、计划单、改单和 OCO 按 Classic endpoint 单独能力登记。 | Spot → USDT-Futures Classic OneWay/Hedge → conditional/protective → amend/reconcile |
| Bitget UTA | 不混用 Classic `marginMode/marginCoin` 请求形状；按 UTA `category/qty/posSide` 与 account settings 处理。UTA strategy endpoints 的 OCO 和 trailing 支持随产品线不同：官方矩阵中 OCO 对 Spot/Margin 可用但对 USDT/COIN Futures 不可用，trailing 也有产品差异。锁定 CCXT 版本未暴露能力时，先评估升级并跑请求契约；必要时增加独立 UTA adapter，不伪装成通用 CCXT 支持。 | UTA 普通单 → `tpsl/trigger` → 按产品支持的 `oco/trailing_stop` → sub-order 查询/恢复 |

来源合同须随实现复核：[OKX V5](https://my.okx.com/docs-v5/en/)、[Binance USDⓈ-M trade API](https://developers.binance.com/docs/derivatives/usds-margined-futures/trade/rest-api/New-Order)、[Bitget UTA Strategy Order](https://www.bitget.com/legacy-docs/uta/strategy/Place-Strategy-Order)、[CCXT createOrder capabilities](https://github.com/ccxt/ccxt/wiki/Manual)。官方接口支持只说明可实现，不说明当前牵星或当前 CCXT 版本已经支持。

## 6. 内置策略和开箱即用体验

不重复实现已有 17 种信号。将其整理成版本化 **Strategy Recipe**，每条包含策略目的、适用产品/时间周期、可调参数、预热长度、目标仓位规则、允许做空条件、成本模型、退出/保护意图、示例数据要求、风险说明和已验证入口。

第一批交付：

- 单标的模板：趋势（SMA/EMA/MACD/Donchian/ATR/Keltner/波动突破）、反转（RSI/Bollinger/mean reversion/VWAP）、网格和 momentum。
- 双腿模板：pairs、spot/perpetual basis、spot/futures、cross-venue；必须声明两腿数据、数量/对冲比例、资金费/借贷成本、腿不同步和部分成交风险。
- 默认 short policy：Spot Cash 不做空；Spot Margin 须显式开通/借币规则；Perpetual/Future 只有产品规格、账户权限、持仓模式、杠杆和 RiskGate 验证通过后才能开空。
- `quickstart --strategy` 生成配方、样例配置与报告；真实数据 quickstart 显式指定数据源/市场/时间范围，不用合成数据冒充行情。
- 策略结果必须分开报告 long/short 贡献、仓位暴露、换手、资金费、手续费、滑点、回撤、时间区间和基准。默认参数是可运行起点，不保证收益。

## 7. 行情、回测和效率

### 7.1 数据入口闭环

Provider registry 统一历史 OHLCV、实时 Bar、trades、L1/L2 的 market/timeframe/interval、since/end、分页、rate limit、retry、cursor、source version。每次导入输出 QualityReport：覆盖区间、缺失/重复/乱序、空量、异常价格、交易时段、未闭合 Bar、时区和采样间隔；任何自动补值必须是显式的研究选择，且进入 Run identity。

长期缓存按内容寻址；下载与交易所执行配置分开。真实数据快照包含 provider/version、市场规格版本、source hash、获取时间与许可元数据。支持增量拉取、断点续取与按限频预算做并发；数据源无法覆盖时明确失败，不静默切源。

### 7.2 回测正确性

统一表达 next-bar-open、tick/order-book 撮合、成交优先级、部分成交、队列位置、费用层级、资金费、借贷、滑点、冲击成本、价格限制和延迟。回测报告标出使用数据粒度能证明的内容；15m bar 不声称还原盘口成交。

Common test corpus 覆盖未来数据、warmup、重复信号、long/short、做空限制、手续费、多币种费用、funding、止损触发 gap、OCO 同时触发/部分成交、精度边界、时区和断档。每个撮合模型附可读假设和参数。

### 7.3 可复现的竞品性能测试

建立 `qx-bench` 标准数据集和固定容器/机器：

| 工作负载 | 固定条件 | 主要指标 |
|---|---|---|
| 单策略 Bar 回测 | BTC/USDT 15m、180 天、同费用/滑点/仓位/策略参数；另用权益数据作独立组 | bars/s、运行时间、峰值 RSS、结果一致性 |
| 多策略参数批次 | 固定 50/500/5000 配置、同样本/OOS split、相同随机种子 | runs/s、总耗时、CPU 利用率、峰值 RSS、失败候选比例 |

2026-11-11 已完成 Windows Release 的初始 CLI 基线，新增进程峰值 RSS 与可用进程树资源采样，并锁定源码指纹：Ryzen 7 8700G 上合成 1k/8k/64k Bar 的 p50 为 545.336/786.574/2222.248 ms，64k 峰值 RSS 为 207.13 MiB，7 次重复结果 hash 稳定。证据为 `maturity/evidence/backtest-e2e-windows-ryzen7-8700g-2026-11-11.json`。该合成样本只建立了资源采样底座，不代表真实行情 profile；Linux 固定 runner、多策略/多标的负载、优化前后同源对照和竞品等价对照当时仍未完成，当前无性能领先结论。

## 11. 主要风险与明确不做

- 不以模拟结果或假 exchange 回复冒充沙盒/实盘证据；不自动注册交易所账户。
- 不以本地 OCO 双单加“触发后再撤另一单”冒充交易所原子 OCO；除非明确名为 synthetic OCO、其超额成交风险有上限且用户显式启用，否则不开放。
- 不因向量化回测更快而用它替代订单队列/部分成交/多币种账本仿真；向量筛选与事件回测分开报告。
- 不宣称“任何交易所、所有产品、全部账户模式通用”；能力必须细化到产品线和账户模式。
- 不把 9 位 raw 局部改成 18 位；精度升级包含 schema/hash/持久化/跨语言/订单与账本迁移。
- 不把策略默认值称为投资建议或收益保证；所有 recipe 要揭示费用、杠杆、资金费和做空条件。
