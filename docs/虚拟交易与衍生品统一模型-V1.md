# 牵星虚拟交易与衍生品统一模型 V1

更新时间：2026-09-11

## 1. 支持范围

统一模型必须覆盖：

- 现货：Cash 结算、持仓不可为负、成交扣减报价货币并增加基础资产。
- 现货杠杆：Cross/Isolated、借币、利息、可用保证金、强平。
- 永续合约：Linear/Inverse、合约乘数、资金费率、逐仓/全仓、单向/双向持仓。
- 交割合约：到期时间、结算价、交割事件和到期后禁止新开仓。
- 虚拟交易：手续费、滑点、延迟、盘口深度、部分成交、资金费、借贷利息、强平和撮合不确定性。

期权、期权组合保证金和复杂组合保证金需要单独的定价与保证金模型，不把它们伪装成线性合约；本阶段先冻结扩展端口。

## 2. 领域契约

每个 `InstrumentId` 必须绑定不可变版本化规格：

```text
InstrumentSpec
  kind: spot | margin | perpetual | future
  base / quote / settle
  linear / inverse
  contract_size
  price_tick / qty_step / min_qty
  expiry / delivery_price_source
  fee_model
  leverage_limits / leverage_tiers
  margin_modes: cross | isolated
  position_modes: one_way | hedge
```

订单不能只携带 buy/sell 和数量，还必须通过策略/风控上下文表达：

```text
OrderPolicy
  reduce_only
  position_side: long | short | net
  margin_mode
  leverage
  post_only / time_in_force
  trigger_price / stop_loss / take_profit
```

## 3. 保证金和账簿规则

- 初始保证金不能简单等于名义额；应按杠杆和交易所 leverage tier 计算。
- 维持保证金必须按持仓名义额、阶梯和方向计算。
- 可用权益 = 现金/抵押物 + 未实现盈亏 - 初始保证金占用 - 费用/利息/资金费。

订单簿逐笔回测还提供确定性的 `OrderBookExecutionModel`：默认保持逐档吃单；配置后可注入快照级延迟、限价单队列前置量和成交价冲击，参数必须随回测假设和 RunManifest 保存。该模型是可重复的执行假设，不等同于交易所真实 L3 队列，真实队列/撤单竞态仍需逐交易所数据验收。
- 强平检查必须使用标记价格/指数价格策略，不能直接使用最新成交价替代。
- 资金费、借贷利息、结算和强平都是独立事实，必须写入 EventLog/Ledger。
- Cross 账户共享抵押物；Isolated 账户按 instrument/position 分隔抵押物。
- Hedge 模式分别维护 long/short；One-way 模式维护净持仓；禁止隐式互相抵销。

## 4. 回测语义

回测必须在同一事件流中处理：

```text
Market/Index/Mark
  → Signal → PortfolioTarget → RiskGate
  → OrderIntent + OrderPolicy
  → MatchingEngine
  → Fill/Fee
  → Funding/Interest/Settlement/Liquidation
  → Ledger/Equity/Margin/RunManifest
```

每次回测报告必须保存：合约规格版本、杠杆、保证金模式、持仓模式、费率、资金费输入、标记价格来源、强平规则、滑点/延迟模型和数据摘要。

## 5. 当前落地状态

已落地第一轮：`qx-core` 统一产品/保证金/杠杆/持仓策略模型；`qx-xingban` Bar 回测已把 Funding、Interest、Delivery 和按维持保证金触发的 Liquidation 写入 EventLog/Ledger；CCXT 订单策略会在公共 Worker 边界调用 margin mode、leverage、position mode，并通过统一订单事件归约。

仍未宣称完成：交易所特定的跨币种抵押品折扣、Inverse 真实账单结算、分层强平价格的交易所差异、交割合约多合约规格、CCXT Pro 用户流和真实沙盒验收；核心定点模型与本地回测已覆盖跨币种估值、Inverse PnL、阶梯保证金、负债净额和强平事件，实盘交易所返回的强平价仍只作为风险观察快照。

## 6. 实盘语义

公共 CCXT 只负责交易所调用；牵星负责统一状态和事实：

- `setMarginMode/setLeverage/setPositionMode` 必须在交易路由初始化阶段显式确认。
- `createOrder` 必须携带 `reduceOnly`、`positionSide`、`marginMode` 等策略意图，不由交易所默认值猜测。
- 订单提交成功但响应丢失时进入 Unknown，必须通过 `fetchOrder/openOrders/positions/trades` 对账后恢复。
- 交易所不支持某统一方法时返回 CapabilityUnsupported，禁止静默降级为错误语义。
- 实盘回报和回测 Fill 都归一化为同一 `RuntimeEvent`，再由 Ledger 归约。

## 7. 多策略

策略只产生带归因的 Signal/PortfolioTarget；多个策略通过 `SignalMerger` 确定性合并，随后统一经过账户、产品、杠杆、保证金和风险限额。每笔成交都保留 strategy_id、signal_id、intent_id 和 OrderPolicy。

## 8. 实施阶段

1. 完成 CCXT 市场能力快照到 `InstrumentSpec` 的转换。
2. 在 Rust 增加 `OrderPolicy`、MarginMode、PositionMode 和合约订单约束。
3. 扩展回测引擎：杠杆、Cross/Isolated、Funding、Interest、Liquidation、Delivery。
4. 将 CCXT JSONL Worker 接入 MarketData/Execution/Reconcile Worker。
5. 用 Binance/OKX/Bybit sandbox 分别验收现货、杠杆、Linear Swap；真实资金交易必须最后进行。
