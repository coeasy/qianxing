# 多语言 SDK 升级实施记录

对应方案：[牵星Qianxing-多语言SDK全能力升级与重构实施方案-2026-10-11.md](牵星Qianxing-多语言SDK全能力升级与重构实施方案-2026-10-11.md)

## 本轮交付

- 将 `qx-provider` 接入 `qx-python` 原生扩展；Python Provider adapter 通过 Rust `ProviderRegistry` 完成 capability 校验、候选排序、failover、来源身份与数据载荷校验。
- 增加 Rust `ProviderResult::from_payloads`，由共享 Rust 代码生成 RawRecord 与结果摘要，语言绑定无需复制指纹算法。
- 新增 `qianxing.data` 的 ProviderQuery、ProviderCapability、ProviderResponse 和 ProviderRegistry；支持将严格 Bar 查询结果标准化成共享 BarFrame。
- 新增 `ProviderAdapterError`、`ProviderManualInterventionError`、`ProviderPermanentError` 三类失败语义，分别映射至 Rust failover、人工介入终止和永久错误。
- 新增 `ProviderRegistry.run_backtest`：只冻结经 Rust 校验的 BarFrame；相同文件可重用，不同内容拒绝覆盖；回测继续调用原 Rust `qx-app` 用例。
- 更新 Python SDK 说明、Rust SDK 迁移指南、Provider 能力矩阵、数据主链调用图与架构门禁名册。

## 本轮验证

- `cargo test -p qx-provider`：8 个单元测试和 1 个集成测试通过。
- `cargo build -p qx-python`：通过；构建后用当前扩展运行 Python 测试。
- Python 全量单测：117 项通过。
- `tools/check_architecture.py`：1096 项通过。
- `cargo fmt --all` 与 `git diff --check`：通过。
- Python 端到端用例覆盖 Rust failover、人工介入不 failover、Bar 质量门拒绝非法 OHLC、BarFrame 冻结及真实 Rust 回测。
- 推送后构建 Windows CPython stable-ABI wheel：`qianxing-0.1.0-cp310-abi3-win_amd64.whl`，SHA-256 `aa61334d20c5ea5b0ceeaeb146d6b181c14b087a77f5d33a146059c659c40c15`；`tools/check_python_wheel.py` 验证 wheel 标签与内含原生扩展。
- 将该 wheel 离线安装到独立虚拟环境，并从安装包执行 Python Provider→Rust BarFrame→Rust 回测，成功得到 1 笔成交。

## 尚未达到方案全部完成/发布门槛

- Python Provider 已贯通历史 Bar 与 Quote 订单簿快照；实时订阅、分页续取、限流器、盘口增量/修订/公司行为一致性与各真实源 conformance 仍需逐项实现和验收。
- Bar Provider 可生成并冻结 `DatasetManifestV2`，经 `DatasetSpec` 校验后运行 Python/Rust 回测；Rust SDK/C++ SDK 自动 manifest 工作流、多组件 DatasetBundle 和任意数据导入流程未完成。
- Quote Provider 到 Rust `DepthFrame` 与 Tick/OrderBook 回测已通过本地端到端验收；外部实时行情、跨源深度序列与真实源 conformance 未验收。
- C++ Provider adapter 尚未实现。
- 组合级多账户资金竞争、跨策略调度与风险聚合、跨市场账户账簿，以及多交易所完整费率/撮合 conformance 仍未闭环。
- Paper/Live 客户端入口存在，但实盘交易所全生命周期 testnet conformance 与人工验收未完成；不据此宣称 Live 已验证。
- 跨平台干净环境安装矩阵、C++ 默认 HTTP transport、完整发布制品与供应链验证仍未完成。

本记录只证明上述交付及本轮验证，不把方案目标或符号存在等同于功能已发布。

## 增量：Python 策略目录发现

- Python SDK 新增 `list_builtin_strategies()`，元数据由 Rust `qx-strategy` 的唯一策略名册生成，包含名称、说明、信号旋钮和是否要求参考腿；避免 Python SDK 硬编码目录后与 Rust 漂移。
- Python 顶层与 `qianxing.core` 导出 `BuiltinStrategyInfo` 和发现函数；README 提供目录选择后调用共享 Rust 回测的示例。
- 新增行为用例核对 Rust 目录与 Python 类型可选项一致（17 个策略），并从目录中选出 EMA 策略运行和复核 Rust 回测结果。
- 验证：`cargo fmt --all --check`、`git diff --check` 通过；Rust Python 扩展构建成功；Python 全量单测 119 项通过；`python tools/check_architecture.py` 1096 项全部通过。
- 提交 `6a685a8` 推送后构建 release wheel：`qianxing-0.1.0-cp310-abi3-win_amd64.whl`，SHA-256 `91a46d3bc5f828409c681f4ea73c32123a7934124acac849fb367907509ab83c`；`tools/check_python_wheel.py` 通过。
- 将 wheel 离线安装至独立虚拟环境，发现 17 个 Rust 策略；选取 EMA 策略调用共享 Rust 回测并成功 `verify_run`。

## 增量：Python Quote Provider 接入 Tick/OrderBook 回测

- 扩展 Python `ProviderRegistry`：Quote 载荷按版本化 OrderBookSnapshot 解析，Rust 核对数据类型、唯一标的、事件时间/血缘一致性、盘口价格数量约束、L1 档位约束和递增序列，再生成带 query 摘要的 DepthFrame。
- 新增 `fetch_depth_frame` 与 `run_depth_backtest`，数据冻结沿用同一份不可覆盖输入逻辑；回测、撮合与复核继续调用 Rust `qx-app`/深度内核，不在 Python 重做撮合。
- 添加端到端正向用例（Quote Provider→Rust DepthFrame→L1 回测→verify）及事件时间错配拒绝用例；更新 Python 数据分层名册、SDK 文档、量化场景清单和 Provider 能力限制。
- 验证：`cargo check -p qx-python`、`cargo test --offline -p qx-provider -p qx-python`（Provider 8 项 + provenance 集成 1 项）、Python 全量单测 121 项通过；修复入口文件行数预算后，`tools/check_architecture.py` 连续三轮均 1096 项通过。
- 提交 `3c32fb3` 推送后构建 release wheel：`qianxing-0.1.0-cp310-abi3-win_amd64.whl`，SHA-256 `649a2ab10b18e754fb062f4dd05b1fd8265a0819252fc50580fd21a7c2f1aeb8`；`tools/check_python_wheel.py` 通过。
- 将 wheel 离线安装至独立虚拟环境，使用安装包执行 80 条 Quote 快照→Rust DepthFrame→L1 深度回测→`verify_depth_run`，同时发现 Rust 的 17 个内置策略，全部通过。

## 增量：Python Provider 自动生成 DatasetManifestV2

- 新增 Rust 原生 `fetch_bar_dataset_json`：先经 Rust ProviderRegistry 获取与校验 Bar 结果，再由共享 `qx-data` 生成规范数据指纹、内容 SHA-256、质量报告、Provider lineage 与版本化 `DatasetManifestV2`。
- 新增 `fetch_bar_dataset` 和 `run_backtest_with_manifest`：调用方显式给出数据集身份、区间毫秒数及时区；SDK 冻结原始 Rust BarFrame 与 manifest，调用 Rust `DatasetSpec` 校验后执行共享 Rust 回测并返回校验结果。
- 正向用例核对 manifest 身份/指纹/质量报告、冻结文件、DatasetSpec 结果及回测复核；保留已有不可覆盖策略。
- 验证：`cargo check -p qx-python`、Rust Python 扩展构建、Python Provider 专项 7 项、Python 全量单测 122 项通过；修复量化场景记录缺少数值观测后，`tools/check_architecture.py` 连续三轮均 1096 项通过。
- 提交 `27947e2` 推送后构建 release wheel：`qianxing-0.1.0-cp310-abi3-win_amd64.whl`，SHA-256 `7ef6b0822c5fe2e9052ad536da1eb9887625ae30f11134ba79a258cbdf6f622e`；wheel 标签/原生扩展校验通过。
- 将 wheel 离线安装至全新虚拟环境，并从安装包运行 Provider 专项与策略目录测试共 9 项；Bar manifest→DatasetSpec→Rust 回测、Quote→DepthFrame→Rust 深度回测、策略目录发现与复核均通过。

## 增量：确定性组合资金规划

- 新增 `qx-zhenlu` 共享资金分配器，组合预算与每个账户可用现金共同限额；低数字优先级先分配，同优先级按策略 ID 排序，结果不依赖输入/线程到达顺序。重复账户/策略、未知账户、负金额、非法身份和超大输入 fail-closed。
- 经 `qx-app::plan_capital_allocation` 和 Python SDK 暴露相同 schema 的规划入口；它只生成资金分配计划，不提交订单，也未接入组合回测或 Paper/Live 交易。Rust/C++ SDK、HTTP API/UI 仍未接入。
- 验证：资金分配领域用例 2 项通过；`qx-app` 全量 83 项 + 独立消费者 2 项通过；`cargo check --offline -p qx-app -p qx-python`、`cargo fmt --all -- --check`、`git diff --check` 通过。测试设置 `TEMP/TMP=target/test-temp`，绕过本机默认临时目录拒绝创建的问题。
- 本增量仍属能力拼接的中间步骤；不将“确定性资金规划”表述为“多账户多策略组合交易已贯通”。
