# 牵星 Qianxing：Freqtrade 对标优化与实施方案

> 更新：2026-10-23。本文记录本轮确认的产品边界、落地路线和验收口径。`bigget` 按 Bitget 处理。

## 1. 目标与边界

牵星面向多语言策略研究、确定性回测和可审计执行。对标 Freqtrade 时，重点吸收其策略开发体验、市场数据接入、参数搜索和回测产物管理；交易规则、资金账本、撮合、风险校验和重放仍由共享 Rust 内核负责，Python/C++/CLI/API 作为接入面，不各自维护一套成交逻辑。

本方案优先交付以下组合：

- OKX、Binance、Bitget 的多标的 Bar 回测。
- 单交易所单账户独立回测、单账户多标的共享账本回测，以及多交易所多账户联合报告。
- 现货和合约回测；合约支持杠杆、订单保证金模式、保证金档位和资金费。
- 实盘/供应商连接代码继续开发；本阶段不发实盘订单、不调用交易所沙盒下单，也不把未验收能力标记为可实盘。
- 对低价小币种保留交易所的价格 tick、数量 step、最小数量和最小名义金额，不用浮点近似交易精度。

## 2. 设计决策

### 2.1 市场与账户边界

`MultiMarketBacktestSpec` 表示一个账户，可包含 1..=32 个异步 Bar 市场。每个市场独立绑定行情文件、产品规格、费率、订单策略、保证金模型、资金费和策略槽，市场事件进入同一个 Rust 组合引擎及同一账户 Ledger。一个市场仍走相同组合内核，避免单市场和多市场出现不同成交语义。

`MultiAccountJointBacktestSpec` 表示 OKX/Binance/Bitget 上 2..=32 个独立交易所账户组，总计最多 256 个标的。每组账户复用共享账户多市场回测用例，各自持有本金、保证金和产物；顶层只汇总权益、收益、回撤和成交。当前不做跨账户保证金净额，也不做不同结算币种之间的 FX 换算，统一要求结算币种一致。

### 2.2 合约杠杆与资金费

产品身份必须来自冻结的 `TradingInstrumentSpec` 或规范化 CCXT 市场快照。衍生品订单需要有效的 `OrderPolicy`；杠杆不得超过产品上限或当前名义金额档位上限。保证金按冻结的杠杆模型或阶梯模型计算，Spot 保持现金/1x 语义。资金费可以使用常量费率或带标的和 UTC 结算时间的历史事件；现货拒绝资金费输入，历史费率与常量费率不能混用。

回测产物要保留市场规格来源、订单策略、保证金参数、资金费输入、账本流水、逐市场成交和权益贡献，确保指标能追溯到输入与执行假设。

### 2.3 小币种数值精度

内部金额和数量以 `i128` 定点 raw 值计算，统一标度为 1e9；交易所精度经 CCXT adapter 归一化为价格 tick、数量 step、最小数量和 quote 最小名义金额。订单数量按 step 约束后再检查最小数量/名义金额；Bar 市场单用最后可见价格校验名义金额，订单簿市场单用同时间点对应方向的最佳报价，限价单另校验价格 tick。拒绝精度超限、最小名义金额不满足或无法表示的市场规格。展示层可格式化数值，但请求、签名、撮合和归因不得经过 IEEE-754 `float` 造成舍入。

### 2.4 应用接入

联合账户用例提供 Rust 稳定 SDK、CLI、HTTP、Python 与 C++ 客户端入口；同步调用直接返回结果，异步调用通过 RunHandle/远端任务句柄管理。Web Console 的扩展研究面板通过版本化 JSON 提交同一路由。所有入口共享 schema、规格校验、市场准备、回测内核和产物结构。API 将数据输入限制在配置的数据根目录，产物路径由服务端生成。

## 3. 研究能力改进

继续保持 Freqtrade 式可迭代研究体验，同时补足回测可信度：

1. 策略未来数据与预热偏差诊断：逐事件检查可见行情边界，报告 look-ahead、预热长度和样本不足问题。
2. 自适应参数搜索：有界、可取消、确定性排序；记录剪枝、训练窗/OOS 和跨折稳健性，不把训练集最优结果冒充样本外结论。
3. 交互式研究报告：统一展示权益、回撤、成交、成本、资金费、市场归因、候选排名与可复核事件；原始 raw 数值保持精确。
4. 供应商验收与容量画像：区分公开只读数据、Testnet/Demo 写操作和生产交易能力；容量结果附机器、数据规模、并发数和 RSS/CPU 证据。

这些研究产物不得替代交易所真实成交验证，也不得作为实盘能力门控的唯一证据。

## 4. 本轮落地状态

已纳入代码的范围：

- 多市场 Bar 最小数量从 3 调整到 1；加入逐市场资金费输入和 CCXT 原始市场快照解析。
- 联合账户规格、校验、独立账户运行、允许不同账户持有重叠标的、汇总权益/成交产物和可取消 RunHandle。
- CLI、Rust SDK、HTTP、Python 与 C++ 同步/异步入口、Web Console 扩展研究入口与 schema/成熟度登记。
- 小币种 1e-9 tick / 数量 step 的 CCXT 精度案例，以及低价现货精确 raw 运算与 quote 最小名义金额准入测试。
- 合约规格、杠杆、阶梯保证金和资金费接入共享多市场 Rust 引擎。

明确限制：联合账户目前只汇总，不跨账户净额；多市场 Tick/OrderBook 合约组合保证金仍单独列为后续能力；真实交易链路仅做实现，不做供应商沙盒下单或实盘验证。

## 5. 发布验收清单

- Rust：检查应用/API/CLI/Python/SDK 与测试目标；运行单账户杠杆、多市场和联合账户集成测试，验证重放、幂等、取消、越权拒绝和非法市场规格拒绝。
- API/前端/客户端：逐项比较实现路由、Python/C++ 客户端声明、两张部署端点表、`maturity/http_route_manifest.json`、能力矩阵和 Web Console 路由；校验异步状态、结果和取消路径。
- Python：检查稳定命名空间、DTO 字段与 Rust schema 一致；运行 SDK、CCXT 市场精度和 app 用例测试。
- 数值：使用低价小币种测试精确 tick/step、最小数量/quote 名义金额、raw 成交与报表序列化；确认小数不得被 `float` 改写，并验证市场单只用参考价估算成本、不把参考价误当限价 tick。
- 研究产物：检查报告携带市场、策略、成本、杠杆、保证金、资金费和数据指纹；输入相同可复现，run_id 冲突时异内容拒绝覆盖。
- 外部执行：维持“代码已实现”与“交易所已验收”两个状态。没有授权凭据、明确测试环境和对应证据时，不发布已验收或可实盘能力声明。
- 发布：版本号、变更记录、CLI 包、Python wheel、C++ 示例/头文件和安装文档必须与同一 schema 版本对齐；构建完成后再给出发布候选，不以单 crate 编译通过代替发布验收。
