# 牵星工业化易用性收口指南 V1

本指南是当前代码的统一使用入口。推荐先完成回测，再完成 Paper 主链路验收，最后在部署机执行实盘前置检查。所有入口都复用同一份运行时配置、策略契约、风险门禁、订单队列和 Ledger，不会因为换成快捷命令而绕过核心链路。

## 1. 最短可用路径

在仓库根目录执行：

```powershell
# 生成本地配置；已有文件默认拒绝覆盖
cargo run -p qx-cli -- init qianxing.runtime.json

# 使用默认策略回测配置和 BarFrame
cargo run -p qx-cli -- backtest

# 验收 Scheduler → Strategy → Paper Execution → Ledger
cargo run -p qx-cli -- paper-check deploy/qianxing.runtime.paper-strategy.example.json
```

`init` 生成的是不含交易凭据的本地示例配置。需要覆盖时必须显式使用 `--force`：

```powershell
cargo run -p qx-cli -- init qianxing.runtime.json --force
```

## 2. 四类入口的职责

| 入口 | 作用 | 是否连接交易所 | 是否可能下真实订单 |
|---|---|---:|---:|
| `backtest` | 跨语言策略进入统一 Rust 回测撮合 | 否 | 否 |
| `paper-check` | 验收调度、策略、Paper 执行、Ledger 主链路 | 否 | 否 |
| `runtime-check` | 检查拓扑、配置解析、运行时健康与指纹 | 否 | 否 |
| `live-check` | 实盘启动前静态门禁，检查证书、凭据来源、规格和研究快照 | 否 | 否 |

`live-check` 只是发布前置检查，不等于真实账户验收，也不会替代交易所 sandbox、网络连通性、用户流和对账验收。真实运行仍需显式启动对应 worker。

## 3. 回测与 Paper

### 3.1 内置策略

当前提供 17 个不依赖外部 Python 环境的内置 Bar 策略：

```powershell
cargo run -p qx-cli -- builtin-strategies
```

策略包括 `sma_cross`、`ema_cross`、`macd`、`rsi`、`bollinger`、`donchian_breakout`、`momentum`、`mean_reversion`、`grid` 和 `atr_trend`。它们统一输出目标仓位差额，仍然经过 RiskGate、OMS 和撮合引擎。

直接回测：

```powershell
cargo run --release -p qx-cli -- builtin-backtest `
  macd deploy/qianxing.bar-frame.example.json `
  deploy/qianxing.binance.spot.spec.json 1
```

`quantity` 是策略目标仓位的整数单位；合约策略必须提供对应的 market spec。内置策略也可以写入 runtime 配置，并通过统一策略回测入口执行：

```powershell
cargo run --release -p qx-cli -- strategy-backtest `
  deploy/qianxing.runtime.builtin-strategy.example.json `
  deploy/qianxing.bar-frame.example.json
```

运行时配置使用 `builtin_strategy` 选择策略，使用 `bars_snapshot_path` 提供 K 线窗口。实时模式额外设置 `live_enabled=true`、`live_timeframe`、`live_history_limit` 和 `live_closed_only=true`；CCXT MarketData worker 会持续维护闭合 BarFrame，Strategy worker 以快照摘要作为幂等键触发策略任务，输出仍进入原有 RiskGate、OMS 和 Execution 链路。`pairs_arbitrage`、`cross_venue_arbitrage`、`basis_arbitrage` 与 `spot_futures_arbitrage` 需要 `builtin_reference_instrument` 和 `builtin_reference_bars_snapshot_path`；多交易所时两条腿由各自的 CCXT REST worker 更新。

如果不需要保留中间 BarFrame，可直接从公共 CCXT 拉取并回测：

```powershell
cargo run --release -p qx-cli -- ccxt-builtin-backtest `
  deploy/qianxing.ccxt.exchange.example.json `
  macd BTC/USDT.OKX 1704067200000 1706745600000 1h `
  deploy/qianxing.ccxt.okx.perpetual.spec.json 1
```

该命令只在获取阶段访问 CCXT，撮合和指标计算仍在本地 Rust 引擎完成；需要长期复现、审计或多人共享时，优先使用三步式快照流程保存 BarFrame。

指定输入文件时：

```powershell
cargo run --release -p qx-cli -- backtest `
  deploy/qianxing.runtime.strategy-backtest.example.json `
  deploy/qianxing.bar-frame.example.json `
  deploy/qianxing.binance.spot.spec.json
```

该命令支持现有 Rust、Python、C++ JSONL 策略契约，以及 `framed_json`、`shared_memory_json` 和 `shared_memory_columnar` 传输模式。成交、费用、保证金、持仓和结果哈希仍由统一回测引擎处理。

多标的、多币种和多参数研究可使用并行批量入口：

```powershell
cargo run --release -p qx-cli -- fast-backtest `
  deploy/qianxing.fast-backtest.example.json
```

每个 `jobs[]` 使用独立 runtime、BarFrame 和可选 market spec，账户与结果相互隔离；多个策略实例仍可通过同一 runtime 的 `strategies[]` 配置。

Paper 主链路使用：

```powershell
cargo run --release -p qx-cli -- paper-check deploy/qianxing.runtime.paper-strategy.example.json
```

需要单独验证 Paper Venue 的接受、报价成交、断线转对账和恢复契约时，仍使用兼容入口：

```powershell
cargo run --release -p qx-cli -- paper
```

## 4. 实盘发布前

先复制并按部署环境修改 production 配置，再计算并写入配置锁。`config_fingerprint` 必须来自最终发布文件，不能使用模板中的 `null`：

```powershell
cargo run --release -p qx-cli -- runtime-check deploy/qianxing.runtime.production.json
cargo run --release -p qx-cli -- live-check deploy/qianxing.runtime.production.json
```

`live-check` 会拒绝或提示以下问题：

- environment 不是 `production`，或没有有效的 `config_fingerprint`；
- TLS 证书链、私钥、客户端 CA 不存在；
- Execution 缺少交易品种规格、订单/持仓名义额上限，或错误配置为 Paper；
- UserStream、Execution、Reconciler 的凭据环境变量/凭据文件不可用；
- 生产策略的研究快照文件不存在；
- API 只绑定本机地址时给出部署提醒。

凭据检查只验证引用是否可用，不输出 key、secret、余额或订单内容。实盘 worker 启动前仍应先执行公共探测、私有余额探测、用户流连接、单轮对账和 sandbox 小额矩阵。

## 5. 故障处理约定

- 配置解析失败：先修复 JSON 和 `RuntimeConfig` 校验错误，不要通过删除字段绕过门禁。
- `config_fingerprint` 不匹配：重新审核最终配置后重新计算发布指纹，不能直接复制旧指纹。
- 凭据不可用：检查 Secret Manager/CSI 投影或环境变量名称；策略子进程不会继承交易凭据。
- 品种规格不可用：补齐 precision、最小数量、最小名义额、乘数、杠杆和保证金档位后再启动 Execution。
- Paper 有订单但没有 Ledger：保留 `data/qianxing-paper` 和 EventLog，先检查队列终态与执行 worker，不要重复提交相同控制命令。
- 真实账户出现未知状态：停止继续下单，进入 ReconcileRequired，对账确认后再恢复。
