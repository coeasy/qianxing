## 1. 已落地的完整主链

```text
Strategy / ControlCommand
  → EventContext
  → ExecutionGateway
  → RiskPort
  → OrderStore / OMS
  → VenuePort
  → ExecutionFact
  → LiveEventPipeline
  → EventLog
  → ProjectionReducer
  → AccountSnapshot / StateReplica
  → API / WebSocket / Visualization Envelope
```

所有订单和外部回报必须经过这条链。未知结果、空回报、非法回报、身份漂移、
重复回报和投影游标断裂均 fail-closed，并进入对账或重同步路径。

## 2. 本次实现范围

### 2.1 事件与上下文

- `qx-core::EventContext` 统一 tenant、run、account、portfolio、strategy、signal、intent。
- `EventMetadata` 持久化上下文，并将上下文纳入事件摘要。
- 订单注册、余额、持仓、资金流水和成交事实自动补齐上下文；上下文不完整时交易注册拒绝。
- `LiveEventPipeline` 继续承担单写者归约、幂等、事件序列、Ledger/OMS 恢复和共享 EventLog 冲突重试。

### 2.2 统一执行引擎

- `qx-execution::ExecutionGateway` 是标准单腿提交入口。
- 旧 `Venue` 连接器可以通过 `BorrowedVenuePort` 接入，不再因为旧 trait 所有权模型保留第二条正常提交路径。
- 控制命令、订单校验、RiskPort、订单登记、Venue 副作用、标准回报归约和未知结果保护处于同一执行边界。
- 产品规格可以注入统一网关，衍生品成交继续使用带规格的归约路径。
- 多 Venue 多腿执行保留非原子语义；任一腿失败、部分成交或未知结果会停止后续自动提交并生成补偿/对账状态。

### 2.3 多账户投影与查询

- API 以 `account_id + venue_id` 作为投影隔离键。
- 启动恢复遍历全部启用账户 worker，不再只载入第一账户快照。
- 投影在追加前校验账户、Venue、订单、成交和账簿身份；漂移会标记投影 unhealthy，并使 `/ready` 返回 503。
- `ProjectionHealth` 暴露最后投影序号、源摘要和错误原因。

### 2.4 可视化与跨语言 envelope

- 账户快照和实时事件共用 `ProjectionEnvelope`：schema、kind、tenant、run、account、portfolio、Venue、as_of、event_seq、cursor、state_hash、source、lineage、data。
- `/account/snapshot/envelope`、`/events/live` 和 WebSocket 事件均经过 envelope 边界。
- 游标只表示事件序号/状态摘要，不与传输层连接标识混用；历史缺口要求先取快照再重放。
- 原始 `/events` 保留为兼容查询入口；新的可视化客户端应使用 envelope API/实时流。

### 2.5 finkit 与研究边界

- `qx-factor::FactorProviderBinding` 明确 `finkit` provider、版本、artifact schema 和摘要。
- 研究工件进入交易侧前必须经过 `validate_finkit_artifact`，摘要不匹配拒绝绑定。
- qianxing 不把 finkit 的计算实现或 DataFrame 引入交易内核；交易侧只消费已验证、PIT 约束和带血缘的工件。

## 3. 已有且继续作为门禁的能力

- 生产配置：PostgreSQL transactional/distributed-outbox、TLS/mTLS、配置指纹、凭据引用、冻结 InstrumentSpec、订单/持仓名义额上限。
- 消息与恢复：Outbox、NATS JetStream 可选适配、consumer checkpoint、ACK/NAK、重试、DLQ、fencing token 和租约。
- 多语言：JSONL、framed、shared-memory、C ABI 协议；输入输出 schema、PIT、策略身份、artifact 摘要和资源超时校验。
- 插件：manifest schema、依赖拓扑、扩展点冲突、显式 replaces、签名/摘要和启动阶段顺序校验。
- 可观测性：worker heartbeat、Prometheus 文件指标、API metrics、readiness/liveness 分离、对账和恢复状态。

## 4. 外部环境验收门禁

以下内容不能在本地仓库单元测试中伪造为完成；没有真实依赖时必须保持失败：

| 能力 | 已实现的代码门禁 | 还必须提供的外部证据 |
| --- | --- | --- |
| 真实交易所 sandbox | 凭据引用、InstrumentSpec、未知结果保护、对账入口 | sandbox 下下单/撤单/成交/断线/重复回报记录 |
| PostgreSQL HA | 事务 EventLog、连接池、租约/fencing 端口 | 多节点 leader 争抢、旧 leader 写入被拒、备份恢复演练 |
| NATS JetStream | Outbox relay、consumer、checkpoint、DLQ | 真实 stream/consumer 配置、断连、重投、死信和告警记录 |
| 多语言发布 | 版本化协议和超时/摘要校验 | Rust/Python/C++ golden vector、崩溃、超时、非法输出、资源超限矩阵 |
| 动态插件生产隔离 | manifest、权限、签名、依赖和启动校验 | 进程/容器沙箱、资源配额、插件故障隔离和撤销发布 |
| 可视化生产部署 | snapshot + envelope + cursor + readiness | WebSocket 重连、历史缺口、权限、快照恢复和长连接压测 |

任何一项外部证据缺失，`doctor/live-check` 不得标记生产可交易；Paper 和回测
可以在明确的本地 profile 下运行，但结果不能被当作真实交易所或 HA 证明。

## 5. 验收命令与三轮复核

仓库内最低门禁：

```text
cargo +1.98.1-x86_64-pc-windows-msvc fmt --all -- --check
cargo +1.98.1-x86_64-pc-windows-msvc test --workspace --all-targets --no-fail-fast
```

复核必须按三轮执行：

1. **事实链**：每个命令/行情/回报是否只能进入一个 EventLog 和一个 reducer；是否能恢复 OMS、Ledger、投影。
2. **隔离链**：account、Venue、strategy、run、tenant、cursor、凭据和插件权限是否跨边界泄漏。
3. **故障链**：重复、乱序、空回报、身份漂移、断线、超时、投影落后、旧 leader 和外部依赖不可用时是否 fail-closed。
