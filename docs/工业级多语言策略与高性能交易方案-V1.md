# 牵星工业级多语言策略与高性能交易方案 V1

## 1. 目标

牵星必须让同一套策略协议同时服务于回测、Paper 和实盘，并支持 Rust、C++、Python 三种策略实现。策略只产生 `Signal/PortfolioTarget/OrderIntent`，不得直接访问交易所、凭证、Ledger 或控制面。

## 2. 已落地的第一阶段

- 新增 `qx-strategy` Rust SDK，提供 `Strategy` trait、`StrategyContext`、`MarketEvent`、`StrategyDecision` 和多订单 `StrategyOrderIntent`。
- 新增内置 `SmaCrossStrategy`，证明 Rust 原生策略可以返回统一订单意图。
- 现有 Python JSONL 契约兼容旧 `target_qty`，同时支持 `intents[]` 多标的、多订单输出。
- Python worker 支持优先调用 `on_event(request)`，旧 `on_decision(request)` 保留兼容。
- Python Strategy worker 在 Strategy worker 生命周期内复用同一进程，不再每个决策重新启动解释器；单次响应超时后会使请求失败并终止该 worker，避免使用未知状态继续交易。
- Python/C++/其他外部策略 worker 使用最小环境白名单，不继承父进程凭证环境；配置中的敏感 `SECRET/TOKEN/PASSWORD/API_KEY/PRIVATE_KEY/CREDENTIAL` 变量会被拒绝。
- 新增 C++ 稳定 C ABI：`cpp/include/qianxing_strategy.h`，并提供 CMake 示例；Strategy Worker 还支持 `external_executable + external_args + external_env`，Rust/C++ 可编译为独立 JSONL 进程，与 Python 共用超时、崩溃隔离和订单归约链路。
- 新增 `schemas/strategy_api_v1.schema.json` 和协议说明。
- Paper worker 支持 `paper_initial_cash_raw`，以幂等资金事实初始化虚拟账户。
- `qx-xingban` 新增 L1/L2 `OrderBookMatchingEngine`，支持盘口校验、逐档吃单、部分成交、限价约束和手续费；订单簿/ Tick 回测现在可注入 `TradingInstrumentSpec`，衍生品订单显式校验 `OrderPolicy` 并走保证金 Ledger 语义。
- 普通 Bar 回测已提供 `NativeBarStrategy`，L1 Tick 回测已提供 `TickBacktestEngine/NativeTickStrategy`，均复用统一 Strategy API、OMS、Ledger 和 EventLog 因果顺序。
- `qx-cli strategy-backtest runtime.json bar-frame.json [market-spec.json]` 已将 Python 持久 JSONL/`framed_json`/`shared_memory_json`/`shared_memory_columnar` 和 Rust/C++ 外部策略接入同一 Bar 回测引擎；输入只包含当前 Bar 之前的历史，输出仍经统一 OrderIntent/Risk/OMS。`framed_json` 使用版本、序号、长度上限和 CRC32；`shared_memory_json` 使用双向固定槽位 SPSC mmap ring，`shared_memory_columnar` 以 QXCB 固定宽度列承载 Bar 历史，示例见 `deploy/qianxing.runtime.strategy-framed.example.json`、`deploy/qianxing.runtime.strategy-shared.example.json` 与 `deploy/qianxing.runtime.strategy-columnar.example.json`。
- `qx-strategy` 已提供单生产者/单消费者 mmap 共享 ring：固定槽位、原子发布/消费序号、容量背压、payload 长度限制、CRC32 损坏检测，并可直接承载 `StrategyFrame`；Rust Runtime 已将它接入 Python Worker，C++ 示例也已接入同一 QXRB 文件布局。当前共享 ring 仍承载 QXSF JSON 决策帧，Arrow 列式热路径和 P50/P95/P99/P999 基准仍需继续接入。
- 新增 Rust C ABI Host 绑定 `qx-strategy::c_api`，会在释放 C/C++ 插件内存前复制并校验决策；`DynamicCAbiStrategy` 可加载 `qx_strategy_get_vtable` 动态库并保证句柄先于库卸载。
- 新增 `SegmentedEventLogStore` 与 `LiveEventPipeline::open_segmented`，完整日志段不可变、尾段仅追加并由 manifest 摘要校验。

## 3. 统一策略链路

```text
MarketEvent
  → StrategyContext + Strategy
  → StrategyDecision(intents[])
  → RiskGate
  → OMS
  → ExecutionPort
  → VenueEvent
  → EventLog/Ledger
```

Rust 策略 SDK 可在同进程运行；Rust/C++ 策略也可编译成独立 JSONL/framed_json/shared_memory_columnar 进程，C++ 另提供稳定 C ABI；Python 策略通过持久 worker 运行并可使用 shared_memory_json/shared_memory_columnar。QXCB 已将 Bar 数值从 JSON 数组替换为固定宽度列，但完整 Arrow C Data Interface 零拷贝行情生命周期仍需继续接入，不改变 Strategy API。

## 4. 性能分层

### 4.1 低频/研究

Python + Arrow + Parquet，适合因子研究、机器学习、分钟级及以上策略。

### 4.2 实时通用

Rust/C++/Python 持久 worker，控制面可使用 JSONL/Protobuf，订单统一经过 Rust Risk/OMS。

### 4.3 低延迟

Rust/C++ 原生策略 + Arrow C Data Interface/Shared Memory + Lock-free Ring Buffer；热路径不写磁盘、不访问数据库、不执行 JSON 序列化。

## 5. 后续必做项

1. 将 QXCB 定长列式数据面进一步升级为 Protobuf/Arrow C Data Interface 零拷贝行情数据面，并建立完整策略端到端 P50/P95/P99/P999 延迟基准；当前 Python/C++ 已具备同一 QXRB/QXCB 协议和传输层微基准。
2. 在已有订单簿回测闭环上继续补真实 L3 队列、撤单竞态、逐事件冲击校准和完整强平过程；当前已接入产品规格、杠杆/初始保证金门禁、衍生品成交 Ledger 语义，以及可复现的延迟/队列前置量/固定冲击模型。
3. 增加 Paper 初始持仓和组合资金分配的幂等配置。
4. 增加 PostgreSQL、ClickHouse、Parquet 数据湖和 NATS/Redpanda 事件流；当前已有可切换的分段文件 EventLog，数据库/MQ 仍需按相同端口实现。
5. 增加策略包签名、ABI/schema 兼容检查、Sandbox、故障注入和多节点 HA。
6. 将 `qx-cli` 中的具体 worker 继续拆到独立 `qx-strategy-worker`、`qx-paper-worker` 和 `qx-ccxt-worker`；跨语言策略回测入口已落地，后续再拆包。

## 6. 验收标准

- 同一输入、同一版本、同一 seed 下，Rust/C++/Python 策略输出的决策摘要一致。
- 策略崩溃、超时、输出过期、重复 intent、非法数量和越权订单均在 Risk/OMS 前被拒绝。
- 回测、Paper、实盘共享相同的 `OrderIntent → Risk → OMS → VenueEvent → Ledger` 语义。
- 所有实盘订单可通过 `strategy_id/signal_id/intent_id/request_id` 完整追溯。
- 热路径延迟、数据延迟、策略延迟和成交延迟均可观测并可回放。
