## 读法（三条纪律）


1. **数字都是快照**。归档文档里的门禁条数、用例数、`#[test]` 数、行数都是那一轮工作树实测出来的值，
   不是现状。现状只有一个来源：根目录 [`README.md`](../../README.md) 的「交付面一览」与「版本与现状」，它只写当轮实测抓到的数。
2. **`logs/` 不随仓库分发**。这些文档引用的 `logs/sXX_*.txt` 是执行那一轮的**本机**目录，
   `/logs/` 在 `.gitignore` 里，所以 clone 下来看不到。日志在不在不影响判据本身——判据都在
   `tools/check_architecture.py` 与 `crates/*/tests` 里，可以当场重跑。
3. **归档不改结论**。移入这里时只做三件事：加"归档状态"那一节、将仓库根相对的路径提及同步到新位置、
   把指向它们的链接改成 `docs/archive/...`（`CHANGELOG.md` 里共 56 + 14 处路径 token 已同步；2026-10-09
   那一批又同步 11 处）。归档节一律追加在**文末**而不是标题下：活文档里有按行号取证的链接
   （`path:NN` 那种），插在顶部会让那些行号整体下移。正文结论一字未改，也不追改——
   历史里那句"当时是 `[3/8]`"就该留成当时那样。

## 为什么留而不删

更早的方案（V1–V10 各代计划、Barter 对齐稿、可视化终态稿、产品化路线图、差距清单、release note）
在本仓库此前的收口轮里已整体删除，需要回溯时按文件名在 git 历史里取。V11/V12 不照同一办法处理，
理由不是它们结论仍正确，而是**引用面**：`CHANGELOG.md` 有 28 行 / 56 处路径 token 链向 V11、
7 行 / 14 处链向 V12，README 的文档地图也把两者当"实现状态与未完成外部边界"的落点。删掉它们会把这些
逐轮记录的出处打断；移到 `docs/archive/` 只打断路径，而同步路径是一次机械替换、可复核。

2026-10-09 那批七份照同一办法处理：它们的引用面仍在（活文档 {6} 行点名它们，另有同批互指 {5} 处），
删除会把逐轮记录的出处打断，所以只移动并同步路径。同日新建的快照文档不是移动来的——它收的是根 `README.md`
与 `deploy/README.md` 那两轮重写摘出的当轮读数，重写动作自己欠一份留档。

2026-10-10 的 V13 逐轮执行记录是第三种处置：**拆**（不是整份移动，也不是新建）。活台账长到 3,820 行、
逐轮记录占 78%，于是只把 §9.1–§9.47 那一段切出来归档，§1–§8 的审计结论与 §9.48 起的逐轮记录留在活面。
切点选在 §9.48 有两个实测理由：它是「V13 R# 收口」那一代格式的第一节，且 `maturity/capabilities.yaml`
与本文的表格都把它当**活指针**引用（回退面名册）。**原 §号一字未改**——切出来不重编号，是为了让
「`…V13.md` §9.N」这种旧指针按号就能取到，代价只是要同步一批路径 token：`CHANGELOG.md` 21 处、
`竞品对比与易用性改进优化计划-v1.md` 3 处、活面 §1–§8 内部 16 处。活面的 `path:NN` 引用地板随之按实测下调
（`tools/check_architecture.py` 的 `LIVE_DOC_CITATION_FLOOR`）——那些引用没消失，只是从活侧转到了存档侧。
