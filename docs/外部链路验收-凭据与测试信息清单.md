> 1. Binance testnet / 实盘（production）各自**具体需要哪些信息**；

## 1. Binance Testnet（测试网）需要的信息

### 1.1 凭据（2 项，无 passphrase）

| 项目 | 内容 | 落点 |
|---|---|---|
| API Key | Binance Spot Testnet 申请的 key | 环境变量 `QX_BINANCE_TESTNET_API_KEY` |
| Secret Key | 同上配对 secret | 环境变量 `QX_BINANCE_TESTNET_API_SECRET` |

  **注意**：期货测试网（futures.testnet）与现货测试网是两套账号体系，本仓 `qianxing.binance.spot.spec.json`
  是现货规格，请务必在 **Spot Testnet** 申请。
- **无 passphrase**：Binance 不需要、也不接受 passphrase 字段。

### 1.2 端点（已在模板里写死，无需用户再填）

| 用途 | 端点 |
|---|---|
| 行情 WS | `wss://stream.testnet.binance.vision/ws`（模板 `binance-market-testnet.endpoint`） |
| REST/下单 | `api.binance.com` 的 testnet 映射（由 `qx-adapter::binance` 按 `venue_id=binance-testnet` 选） |

### 1.3 配置落点

- 模板：`deploy/qianxing.runtime.binance-testnet.example.json`（`environment: "testnet"`）。
- 三个 worker 的 `credential_env` 都引用上述两个环境变量名：
  `binance-execution-main`、`binance-spread-recovery-main`（默认禁用）、`reconciler-main`。
- 验收脚本 `BASE_CONFIG` 即指向该模板；`EXECUTION_WORKER="binance-execution-main"`、
  `RECONCILE_WORKER="reconciler-main"`。

### 1.4 运行前准备

```bash

export QX_BINANCE_TESTNET_API_SECRET="<你的 testnet secret>"

```

## 3. 能否换成 OKX 测试？——能

### 3.1 可行性

OKX 通过 **CCXT 桥**接入，是 `VenueFamily::Other` 的一等公民。代码路径已完整：
- 入口：`ccxt-market-spec` / `ccxt-fetch-ohlcv` / `ccxt-submit-order` / `ccxt-worker`；
- 提交复用与 Binance **同一个**执行网关与幂等/终态口径；
- 验收脚本 `--venue okx` 已参数化，无需复制脚本。

**换成 OKX 测试的意义**：摆脱对 Binance 测试网账号的依赖，但**仍然需要 OKX 测试网（沙盒）凭据**。
沙盒不等于匿名——OKX 沙盒也要申请 API key/secret/passphrase。所以「换 OKX」解决的是「供应商锁定」，
不是「免凭据」。

### 3.2 OKX 沙盒需要的信息（3 项，含 passphrase）

| 项目 | 内容 | 落点 |
|---|---|---|
| API Key | OKX 沙盒申请的 key | 环境变量 `QX_CCXT_OKX_API_KEY`（写在 CCXT 交易所配置 `credential_env.api_key`） |
| Secret Key | 配对 secret | 环境变量 `QX_CCXT_OKX_SECRET`（`credential_env.secret`） |
| Passphrase | OKX **特有**的口令（创建 API 时自设） | 环境变量 `QX_CCXT_OKX_PASSWORD`（`credential_env.password`） |

- **与 Binance 的关键差异**：OKX 多一个 **passphrase（password）**，少则鉴权直接失败。
- **获取途径**：OKX 开放平台 → 创建 API → 勾选「模拟交易 / 沙盒」→ 得到 key/secret/passphrase。
- 交易所配置：`deploy/qianxing.ccxt.exchange.example.json`
  （`exchange_id:"okx"`、`sandbox:true`、`credential_env` 引用上述三个环境变量名）。
- 运行时配置：`deploy/qianxing.runtime.ccxt.example.json`
  （worker `ccxt-execution-main` / `ccxt-reconciler-main` 的 `endpoint` 指向上面的交易所配置；
  **凭据不写在 runtime worker 的 `credential_env`，而写在被 `endpoint` 引用的 CCXT 交易所配置里**——这是 CCXT 路径与 Binance 路径的唯一结构差异）。
- 下单样例：`deploy/qianxing.submit-order.ccxt-derivatives.example.json`
  （`instrument: "BTC/USDT:USDT.OKX"`、`venue: "OKX"`、永续、`limit: null` 市价、`policy` 块）。

### 3.3 运行前准备

```bash
export QX_CCXT_OKX_API_KEY="<OKX 沙盒 key>"
export QX_CCXT_OKX_SECRET="<OKX 沙盒 secret>"
export QX_CCXT_OKX_PASSWORD="<OKX 沙盒 passphrase>"
python tools/binance_testnet_acceptance.py --venue okx
```

## 4. 外部验收需要准备的测试信息（逐条枚举）

无论 `--venue binance` 还是 `--venue okx`，验收脚本都做以下四段，且**逐段带整体超时 `LEG_BUDGET_SECONDS=180`**：

1. **公开探测（无凭据即可的部分）**
   - binance：`binance-public-probe`（行情/时间端点，不需 key）；
   - okx：`ccxt-market-spec` + `ccxt-fetch-ohlcv`（从交易所配置读规格、拉历史 K 线）。
2. **私有探测（需凭据）**
   - binance：`binance-private-probe`（账户/仓位端点，需 key+secret）；
   - okx：同上由 CCXT 走私有端点。
3. **一次性提交（需凭据，含幂等校验）**
   - binance：`binance-submit-order`；okx：`ccxt-submit-order`；
   - 同一份 SubmitOrder 命令先跑一遍（`request_id` 入控制面），再**用相同 `request_id` 重跑**，
     断言控制面返回「幂等」拒收（`"幂等" in combined`）——验证重复命令不被重复下单。
4. **常驻 worker 循环（需凭据）**
   - binance：`binance-worker`；okx：`ccxt-worker`；跑一轮收尾，验证 worker 真起来、真退出。
5. **对账 + 状态 + 结果包**
   - 调 `reconcile` 与 `status`；把 `passed / failed / timeout / sandbox_tested 是否可翻`
     写进 `maturity/evidence/testnet/<venue>-acceptance-<ts>.json`。

### 4.1 验收「通过」的判定（诚实口径）

- 脚本退出码 0、四段全绿、`request_id` 幂等拒收断言命中、结果包含真实 worker 反馈（非空跑）。
- 但**即便本机脚本跑通**，也只是「用户环境的凭据能驱动链路」；本仓 `sandbox_tested` 翻 `true`
  需要：① 真实凭据在 CI/某环境跑过；② 结果包作为**仓库资产**落盘且被门禁登记。
  当前两者都不具备，故两档维持 `false`。

### 4.2 需要用户提供的信息清单（Checklist）

- [ ] 选择供应商：`binance` 或 `okx`（建议先 OKX 沙盒，避免 Binance 测试网偶发限流）。
- [ ] 对应 API Key / Secret（OKX 还需 Passphrase）。
- [ ] 若 `binance` 实盘：mTLS 证书四件套 + Postgres DSN + 研究快照指纹（见 §2.1）。
- [ ] 一台能出网到交易所端点的机器（本沙箱出网受限，无法代跑）。
- [ ] 跑完后把结果包路径回填到 `maturity/evidence/testnet/` 并在 `capabilities.yaml` 登记
      （这一步由门禁 `external_acceptance_check` / `capabilities_check` 收口）。
