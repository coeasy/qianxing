### 1.3 十六轮审计落地的缺陷驱动修复【已实现 · 在盘】

- **R1（V13 §9.48 及 R1-A…R1-J）**：qx-api 传输层外置 + WS 升级头部判定 + 作用域总线 + `after` 游标 + 轮次界；浏览器准入（CORS 精确 allowlist + OPTIONS 预检 + 连接预算 503 + 查询串百分号解码）；Outbox relay 重试上限/死信/parked 计数/`available_outbox` 下推 LIMIT（重试节奏来自 relay 轮次间隔 `relay_interval_ms` 与租约窗口 `lease_seconds`，**不是逐事件退避**：`ConsumerEngine` 用 `RetryPolicy::attempts_only`，零延时；R4-B 更正此口径）；无界增长与生命周期收口（快照历史淘汰、控制面保留、监督器转发停机、CCXT 泵有界）；联网腿补 subprocess 超时；文档假断言纠正；文档 `path:NN` 引用可达性门禁（#152）；NATS 门后用例在 CI 补执行腿。
- **R2（V13 §9.49，R2-A…R2-F）**：策略 worker stdout 泵由无界 `mpsc::channel()` 改 `mpsc::sync_channel(1)`（与 CCXT 泵同族），断言**折进**已有门禁第 6 颗 `check()`（总条数仍 602）；删 `qx-api` 两个零生产调用公开面（`cors_allowed_origins()` getter、`admission::allowed()`）；`websocket_accept` 降 `pub(crate)`；`max_concurrent_connections()` 文档改诚实口径；【客户端接入】WS「路径闸」假断言按代码事实重写（升级只看 `Upgrade` 头部，无路径 allowlist，无 `/ws`、`/stream` 路由）。
- **R3（V13 §9.50，R3-B）**：`qx-runtime` 策略契约 `to_json_for` 零生产调用（生产只**解码** `from_json_for`），降级为 `#[cfg(test)] pub(crate) fn`。三轮扫描（连通性 / 孤儿与文档失配 / 终止性）各自复核 R1/R2 修复完好，**未发现新的核心断链、孤儿逻辑或死循环**。
- **R4（2026-10-04，R4-A/B/C）**：① **R4-A** CCXT 进程桥的 stdin 写入补上写侧预算（`qx-adapter/src/ccxt.rs` 的 `CcxtProcessClient::call` 把 `write_all` 交给独立线程，主路径按 `write_done.recv_timeout(timeout_ms)` 收口，超时即杀 worker 并留可读诊断）——这是"无预算等待"族的**第三处**，与 R2 的策略宿主（#281）、event consumer handler（#282）同族同修法，之前只有前两处有牙齿；新增 `ccxt_pipe_write_budget_check` 三颗判据（610 → 613）。② **R4-B** 更正 Outbox relay 的口径失实：文档原先写"重试上限/**退避**/死信/parked"，实测 `ConsumerEngine` 用 `RetryPolicy::attempts_only`（零延时），重试节奏来自轮次间隔 `relay_interval_ms` 与租约窗口 `lease_seconds`，**不是逐事件退避**——按代码事实重写，不留会让读者误判的宣称。③ **R4-C** 给零读者判据补上两处**历史盲区**：旧式 `PUB_SURFACE_DEF` 在 `pub const fn` 上把捕获组落到 `fn` 本身（全仓 23 处 `pub const fn` 因此全部映射成 `crate::fn`，而 `fn` 一词到处都是，"零读者"永远数不出来）；`pub use` 重导出行曾被当成"生产读者"（重导出只是把名字摆到 crate 根，没有任何调用）。两处修好后立刻放出 `qx-data::load_bar_batch`（批量装载按 request 逐条校验 provider 不得返回越界行，能力在盘但生产走 `ingest_bars`）与 `qx-core::default_maker_taker`（生产两条执行平面直接读 `DEFAULT_MAKER_BP`/`DEFAULT_TAKER_BP` 常量装配，只有用例在调构造器），各带理由登记进允许清单；并新增一颗元判据把这两处盲区钉住（613 → 614）。R4-C 同时复核了 479 个 `pub struct/enum/trait/type` 与 82 条 `pub use` 重导出，除 `load_bar_batch` 外**全部有生产引用**，允许清单里既有的 27 条零读者登记无一长出读者（无过期项）。

## 2. 目标架构（合并四份文档，去矛盾）【设计意图 · 未排期】

四份文档的目标架构本质是**同一个内核 + 两条产品轨**，合并后不矛盾：

```text
        ┌─────────────────────────────────────────────────────────┐
        │  产品壳轨                                                 │
        │  ┌───────────────┐   ┌──────────────┐   ┌─────────────┐ │
        │  │ qx-cli (单bin) │   │ Web 回测平台  │   │ Tauron 桌面  │ │
        │  │ 运维/研究/发布  │   │ (实验/Run)    │   │ Host+Agent  │ │
        │  └───────┬───────┘   └──────┬───────┘   └──────┬──────┘ │
        └──────────┼──────────────────┼──────────────────┼────────┘
                   └──────────────────┼──────────────────┘
                          ┌───────────▼────────────┐
                          │  Application services   │  ← 从 qx-cli 抽出
                          │  backtest/paper/live/API│
                          │  experiment/run 编排     │
                          └───┬────────────────┬────┘
                    ┌─────────▼──────┐  ┌──────▼───────────────┐
                    │ Runtime engine  │  │ Ports / contracts     │
                    │ supervision     │  │ execution/store/      │
                    │ (拆自 qx-runtime)│  │ scheduler/research    │
                    └─────────┬───────┘  └──────┬───────────────┘
              ┌───────────────▼──┐   ┌──────────▼───┐   ┌──────────────────┐
              │ Domain kernel     │   │ Storage       │   │ External adapters │
              │ core/risk/OMS/    │   │ EventLog      │   │ Venue/Data/Python │
              │ ledger/matching   │   │ Outbox/snapshot│  │ C++/finkit        │
              └───────────────────┘   └───────────────┘   └──────────────────┘
```

### 2.1 稳定核心（【架构审计】§12.1）

收敛一组稳定 contract 类型（`AccountScope`、`InstrumentRef`、`MarketSpec`、`EventId/CorrelationId/SourceOffset/OrderId`、`ExecutionFact`、`ProjectionVersion/SchemaVersion`、`ValuationContext/ValuationResult`），落 `qx-contract` 或 `qx-core` 的 contract 子模块。`qx-core` 保持纯确定性，不依赖 runtime/storage/网络/Python/C ABI。

**与当前事实的关系**：`qx-core` 今天已是确定性内核（`Fixed/Money/Price/Quantity` 的 `i128` 定点、四类身份分离、`EventLog` 单一重放内核）——这是项目最重要的正确性资产，**保持不动**；目标只是把散落的同名模型（`DataProvider`/`Bar`/`StrategyContext`）经显式 adapter 收敛到单点。

### 2.2 事件存储与投影（【架构审计】§12.2）

目标持久化形状：`event_log(log_name, seq, …, digest)` + `outbox(…, attempts, lease, status)` + `projection_checkpoint` + `snapshot`，一个 `append_batch()` 事务同时前移三者；消费者以 `event_id` 幂等、以 fencing token 更新 checkpoint。文件后端实现同语义 WAL + immutable segments，**不再以全量 JSON overwrite 作长期主路径**。

**与当前事实的关系**：今天文件/PG EventLog 写侧仍存在全量内容成本（P1-1）；Outbox relay 的重试上限/死信/parked 计数**已由 R1-C 在盘**，但逐事件退避没有落地（`ConsumerEngine` 的 `RetryPolicy::attempts_only` 零延时，只靠轮次间隔与租约窗口节律，R4-B 更正此口径），「事实与投影在文件后端单事务」（P0-2）同样尚未落地。

### 2.3 Runtime 拆边界（【架构审计】§12.3 / P1-3）

`qx-runtime` 拆 `runtime-config` / `runtime-engine` / `runtime-supervision` / `strategy-contract` 四模块，facade 只留装配。统一 worker lifecycle 词表：Starting/Ready/Degraded/Stopping/Stopped/Failed/Unknown。

**与当前事实的关系**：`strategy_contract` 已是 `qx-runtime` 内子模块（R3-B 刚收口其编码器）；environment 词表单点与 production 判定唯一出口是 fam06「已回退，未排期」。

### 2.4 扩展策略三分类（【架构审计】§12.4）

不再统称「插件」，分：① 编译期组件（Rust 内置策略/撮合/费用）；② 受信任 native extension（C ABI，须显式签名+版本+信任根+profile）；③ 隔离外部 worker（Python/CCXT/finkit，versioned IPC + 资源预算 + 父子监督 + artifact digest）。热插拔优先 WASM/独立进程沙箱，不扩大 in-process `libloading`。

**与当前事实的关系**：多语言契约已版本化（strategy contract schema、C ABI 头镜像门禁 S13、Python worker）；但 P0-3 的 native sandbox 信任根、fam09 的策略声明作用域逐格拒仍「未排期」。

### 2.5 两条产品轨（【Web 平台】+【桌面方案】+【客户端接入】）

- **Web 回测平台**：`Experiment`（多参数展开）→ `Run`（状态机 Queued/Running/Succeeded/Failed/Cancelled）→ 只读结果 + 实时任务事件（SSE/WS）+ 复现。共享回测服务库从 `qx-cli` 装配抽出，**不改变核心事实来源**（同一 `result_hash` 口径）。
- **Tauron 桌面**：三层权限边界（Desktop Host / Qianxing Agent / Web UI），本地回环连接 + Tauron ACL，桌面目录承载数据/运行产物，发布物含 binary/wheel/C++ SDK + SBOM + 签名。
- **客户端接入协议**（两轨共用）：首次加载走快照，增量走事件 + 断线重连（`after` 游标 + 作用域键 `account_id+venue_id`），控制命令走受理→执行者判定→终态退场。

**与当前事实的关系（重要诚实声明）**：`qx-api` 的 WS 升级**只看 `Upgrade` 头部**（刻意不读正文防请求体劫持），把关口是**查询串作用域 + `after` 游标准入**；仓内**没有路径 allowlist，也没有 `/ws`、`/stream` 路由**（现有路由 `/events` 与 GET `/events/live`）。【客户端接入】早期版本把它谎报成「WS 升级路径闸」，R2-E 已按代码事实改口。客户端 MVP 的 `after` 游标 + 作用域键准入**已在盘**（R1-A），但控制面「受理前判执行者、入队失败不回假 202、终态退场」是 fam07「已回退，未排期」。

## 4. 验收标准（合并【架构审计】§14 + 各产品轨）【设计意图 · 未排期】

- **主链路**：同一输入在 debug/release、Rust/Python/C++ strategy 下 `result_hash` 相同；回测完成前必过输入 fingerprint/market spec/risk-cost binding/ReplayVerifier；Paper 同日重跑只显示新增事实，零新增不得宣称重新完成端到端；缺行情/缺规格/未知回报/重复回报/过期 lease/非法精度/未知订单均 fail closed。
- **事件与存储**：append 增量写不随历史全量序列化；N=1k/8k/32k 单次追加 p95 不线性翻倍；崩溃后不丢事实/不重账/可去重/旧 fencing token 不能 ack；迁移旧数据有显式版本与回滚/拒绝策略。
- **状态与生命周期**：所有 Venue 走同一 `ExecutionFact` reducer 与精度/终态门禁；每 worker 报告启动/就绪/降级/停机/退出原因/最后 heartbeat；**每个阻塞 I/O 都有 timeout**（DB connect、HTTP、WS、stdin/stdout、queue claim、handler、shutdown join）；SIGINT/SIGTERM/Windows stop/kill -9/子进程不读 stdin/子进程无响应均有自动化用例。
- **API 与跨语言**：API/snapshot/strategy contract/C ABI/Python SDK 用同一 schema 版本矩阵；新字段默认兼容、未知字段按契约拒绝、删字段至少一个 deprecation cycle；golden corpus 交叉验证；自研 HTTP 必须有 framing/URL/header/keep-alive/WS control frame 覆盖表。
- **发布与运维**：一个 tag 生成可复现 binary/wheel/C++ SDK + commit/target/profile/schema/SBOM/签名/hash；feature matrix（sqlite/postgres/nats/postgres+nats）全 check/test/clippy；service-backend contract 在真实容器执行而非仅编译 ignored tests；venue acceptance 无凭据输出 `skipped`、有凭据输出受控 evidence，二者不得都显示绿色「production ready」。

> **当前已绿的验收面**：feature matrix 的 sqlite 腿在盘；NATS 门后用例已由 R1 补 CI 执行腿（fam13 登记的那颗判据本身仍回退）；阻塞 I/O timeout 的 NATS/WS/CCXT/子进程 stdin 各腿已由 R1/R2/R7 系列逐颗落地并在 610 门禁里有牙齿。

## 7. 排期原则与不做的事

**排期原则**：

1. **先牙齿后功能**——阶段一（恢复 15 族门禁牙齿）优先于任何新功能；没有门禁判据的修复不算完成。
