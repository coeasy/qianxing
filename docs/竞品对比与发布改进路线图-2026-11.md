# Qianxing 竞品对比与发布改进路线图

日期：2026-11-12  
范围：策略回测、研究体验、交易执行、可视化、可观测性与安装发布。  
基线：仓库 `docs/自研量化框架审计与重构方案-V13.md`、`maturity/capabilities.yaml` 及其验收证据。没有证据的能力不写成已完成，也不把代码存在等同于交易所验收。

## 竞品参照

| 方向 | 公开产品基线 | Qianxing 应达到的验收结果 |
|---|---|---|
| 一键研究体验 | RQAlpha 可用单条命令运行策略、输出收益和风险摘要、保存结果并单独绘图 | 新项目从安装到首次离线回测、报告和下一步部署提示不超过 5 条清晰命令；内置策略有可复制模板和统一结果包 |
| 参数研究与效率 | VectorBT 以 NumPy/Numba/Rust 执行向量化批量分析，并提供参数网格和交互图 | 对同一数据、规则和手续费口径提供单策略与批量扫描；以固定硬件公开吞吐、峰值内存、冷/热启动、结果哈希和成本模型，避免只比内核微基准 |
| 事件驱动和分析 | Backtrader 提供事件驱动策略、内置分析器和图表，并支持其列明的若干实盘连接 | 继续共享回测/Paper/live 的订单及风控语义；图表可从收益曲线钻取到成交、订单、持仓和事件；交易所能力按产品/订单类型列出实测状态 |
| 交易所执行 | CCXT 提供统一交易所 API，但统一调用本身不代表订单类型、账户模式、杠杆和保护单语义一致 | 每个连接器声明支持矩阵；在每个交易所逐项验收 Spot/合约、单向/双向持仓、精确数量/金额、保护单、撤单、改单、重启对账和未知结果恢复 |
| 可视化与可观测性 | 竞品提供可交互图表、收益分析器或研究面板 | HTML 报告支持交互缩放与成交标注，导出静态图/CSV/XLSX；运行界面呈现数据新鲜度、订单状态、风险拒单、延迟分位、错误分类、worker 心跳及恢复状态 |

参照来源：[RQAlpha 回测与绘图说明](https://github.com/ricequant/rqalpha/blob/master/docs/source/intro/overview.rst)、[VectorBT 入门](https://vectorbt.dev/)、[Backtrader 功能](https://backtrader.com/home/features/)、[Backtrader 绘图](https://backtrader.com/docu/plotting/plotting/)。产品宣传能力用于确定对标方向；性能和稳定性必须由本仓可复现数据证明。

## 当前差距和执行顺序

### P0：交易链路完整且可恢复

1. 收口 OKX/Binance/Bitget 的一等订单意图矩阵：普通单、止盈止损、触发、OCO、追踪止损、改单；每个能力明确账户模式、产品类型、参数语义、拒绝原因和降级条件。
2. 对每条原生订单组完成提交、权威查询、撤销后二次查询、用户流更新、进程重启恢复、部分成交和未知响应测试。交易所没有稳定腿标识时按精确数量/价格/方向匹配；多重匹配、历史过期或信息不足时围栏并人工对账，禁止猜测和自动重发。
3. Bitget UTA OCO 已接到服务控制与 reconciler：支持提交路由、未成交策略单查询、撤销后核验及零成交终态恢复。触发后通过策略子单与订单详情精确匹配本地止盈/止损腿，再用逐笔成交和手续费核验成交量，并把子单远端身份写回 EventLog；活跃、部分成交及终态都按精确状态归约，未知或歧义继续进入 `ReconcileRequired`。策略子单查询仅保留 7 天，超过查询窗口后的权威恢复、并发双腿成交处理及真实 sandbox 往返仍未验收，能力仍标为 `implemented-unverified`。
4. 完成 CCXT、认证执行和 reconciler worker 的可观测采集：worker 存活、队列年龄、请求/响应耗时分位、错误分类、对账积压、订单组 unresolved 数；指标标签限制 cardinality，不写 API 密钥或用户敏感数据。

### P1：开箱研究体验与回测可信度

1. 打通 `init → doctor → quickstart → data → backtest → report → evidence verify` 的主流程，crypto 与 A 股首跑均提供离线样例；CCXT 首跑只读取公开数据，凭据存在时再提示只读探针和测试网步骤。
2. 策略模板先覆盖 SMA/EMA 趋势、RSI 均值回归、MACD、布林带、突破、定投/网格研究策略；模板必须声明适用市场、参数范围、费用/滑点假设、风险边界及禁止实盘的条件。
3. 增加批量参数扫描、滚动/样本外验证和同配置对比；报告显示交易次数、年化/累计收益、最大回撤、波动、Sharpe、胜率、盈亏比、手续费/资金费率、基准和数据覆盖区间，并写明空值/年化口径。
4. 用真实端到端工作负载定性能目标：半年 15 分钟 K 线、多标的、指标预热、撮合、账本、报告、冷启动和内存；固定源码哈希、CPU/OS、数据哈希和运行命令。每次优化都比较结果哈希或解释预期差异。

### P2：可视化与运维体验

1. 交互式权益/回撤/基准曲线、K 线成交标记、持仓和资金时间线、订单生命周期瀑布、策略日志定位到 bar 与 signal；筛选时间段、标的和策略。
2. 报告统一导出 HTML、JSON、CSV、XLSX 和可复现 EvidenceBundle；离线文件不依赖外部 CDN，运行数据与可分享报告分离。
3. 提供账户/策略总览：数据延迟、worker 心跳、连接状态、未完成订单、风险拒单、撤单/改单待对账、资金和保证金；告警需链接到具体订单、事件和处理建议。
4. 增加结构化日志关联 ID、API/worker 健康探针、重启/故障注入验收与排障文档；敏感配置只从环境/密钥管理读取。

### P3：发布门禁

1. Linux、Windows、macOS 的干净环境安装与卸载；Rust CLI 与 Python wheel 的 ABI、依赖、SBOM/许可证、签名和 provenance 检查。
2. CI 覆盖 Rust/Python/C++ SDK、Linux/PostgreSQL、Windows 长路径、CLI 首跑、报告产物、兼容性与性能回归；外部凭据测试明确标为未运行时，不得算通过。
3. 每个交易所独立保留经授权的 sandbox 往返证据；生产权限、风险限额、行情许可、供应商规格/签名复核与版本签名由发布责任人完成后再打 tag。

## 当前可确认的基线

- 本地能力和未收口项以 [V13 审计记录](自研量化框架审计与重构方案-V13.md) 及能力登记为准。已记录的近期证据包括离线 A 股/crypto quickstart、报告多格式输出、CCXT 订单路径和单条 Binance 公共行情 metrics scrape；这些证据不能替代全部 worker 的端到端 profile 或授权交易所验收。
- Bitget UTA OCO 触发子单现在具备代码级角色匹配、精确成交/费用回查、远端身份持久化及歧义围栏；本地验证为 qx-service 120 项、Python worker 28 项和架构快检 373 项通过。策略子单的 7 天查询窗口、跨重启/并发双腿对账仍需进一步处理；未发送真实 Bitget 请求，也无授权 sandbox 往返证据，因此能力仍为 `implemented-unverified`。
- 不承诺无定义边界的“全面超越”。对标以可复现性能、首次成功耗时、核心链路通过率、状态恢复率、报告交互功能和线上可观测覆盖率逐项验收。
