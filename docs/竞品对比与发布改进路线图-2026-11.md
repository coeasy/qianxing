# Qianxing 竞品对比与发布改进路线图

日期：2026-11-12  
范围：策略回测、研究体验、交易执行、可视化、可观测性与安装发布。  
基线：仓库 `docs/自研量化框架审计与重构方案-V13.md`、`maturity/capabilities.yaml` 及其验收证据。没有证据的能力不写成已完成，也不把代码存在等同于交易所验收。

## 竞品参照

| 方向 | 公开产品基线 | Qianxing 应达到的验收结果 |
|---|---|---|
| 一键研究体验 | RQAlpha 可用单条命令运行策略、输出收益和风险摘要、保存结果并单独绘图 | 新项目从安装到首次离线回测、报告和下一步部署提示不超过 5 条清晰命令；内置策略有可复制模板和统一结果包 |
| 参数研究与效率 | VectorBT 以 NumPy/Numba/Rust 执行向量化批量分析，并提供参数网格和交互图 | 对同一数据、规则和手续费口径提供单策略与批量扫描；以固定硬件公开吞吐、峰值内存、冷/热启动、结果哈希和成本模型，避免只比内核微基准 |
| 事件驱动和分析 | Backtrader 提供事件驱动策略、内置分析器和图表，并支持其列明的若干实盘连接 | 继续共享回测/Paper/live 的订单及风控语义；图表可从收益曲线钻取到成交、订单、持仓和事件；交易所能力按产品/订单类型列出实测状态 |
| 交易所执行 | CCXT 提供统一交易所 API，但统一调用本身不代表订单类型、账户模式、杠杆和保护单语义一致 | 每个连接器声明支持矩阵；在每个交易所逐项验收 Spot/合约、单向/双向持仓、精确数量/金额、保护单、撤单、改单、重启对账和未知结果恢复 |
| 可视化与可观测性 | 竞品提供可交互图表、收益分析器或研究面板 | HTML 报告支持交互缩放与成交标注，导出静态图/CSV/XLSX；运行界面呈现数据新鲜度、订单状态、风险拒单、延迟分位、错误分类、worker 心跳及恢复状态 |

参照来源：[RQAlpha 回测与绘图说明](https://github.com/ricequant/rqalpha/blob/master/docs/source/intro/overview.rst)、[VectorBT 入门](https://vectorbt.dev/)、[Backtrader 功能](https://backtrader.com/home/features/)、[Backtrader 绘图](https://backtrader.com/docu/plotting/plotting/)。产品宣传能力用于确定对标方向；性能和稳定性必须由本仓可复现数据证明。

## 当前差距和执行顺序

### P0：交易链路完整且可恢复

1. 收口 OKX/Binance/Bitget 的一等订单意图矩阵：普通单、止盈止损、触发、OCO、追踪止损、改单；每个能力明确账户模式、产品类型、参数语义、拒绝原因和降级条件。
2. 对每条原生订单组完成提交、权威查询、撤销后二次查询、用户流更新、进程重启恢复、部分成交和未知响应测试。交易所没有稳定腿标识时按精确数量/价格/方向匹配；多重匹配、历史过期或信息不足时围栏并人工对账，禁止猜测和自动重发。
3. Bitget UTA OCO 已接到服务控制与 reconciler：支持提交路由、未成交策略单查询、撤销后二次核验、零成交终态恢复及权威零成交拒绝归约。触发后通过策略子单与订单详情精确匹配本地止盈/止损腿，再用逐笔成交和手续费核验成交量，并把子单远端身份写回 EventLog；未知或歧义继续进入 `ReconcileRequired`。两条腿均有非零成交时，现将两腿成交事实照常入账、保持人工对账围栏，并在报告中输出 `native_order_group_dual_execution` 告警。触发后无可核验子单时，另报 `native_order_group_child_identity_unavailable`，提示人工核对交易所订单/成交历史与 EventLog，禁止凭数量/价格猜测归属或自动重发。Bitget 文档称策略子单接口只能查询父策略单创建后 7 天内生成的子单；普通订单历史虽列出订单/客户订单 ID、委托类型等字段，但未列出父策略单 ID，因此不能据此推断子单归属。相关能力仍为 `implemented-unverified`，未验收真实 sandbox 往返。
4. 完成 CCXT、认证执行和 reconciler worker 的可观测采集：worker 存活、队列年龄、请求/响应耗时分位、错误分类、对账积压、订单组 unresolved 数；指标标签限制 cardinality，不写 API 密钥或用户敏感数据。

### P1：开箱研究体验与回测可信度

1. Rust CLI quickstart 已打通 `init → doctor → backtest → report --evidence → evidence verify-run → status`：builtin/A 股走离线样例，CCXT 走公开行情，并从首次运行起产出可核验 EvidenceBundle。Python sample quickstart 与 `project report --evidence` 复用随 wheel 打包的匹配 CLI 生成并离线核验同类证据，报告状态记录 bundle 路径和摘要。Web Console 的离线首跑现可一键完成安全安装、数据校验、Bar 回测和产物复核；真实数据源下载入口、行情首跑和凭据/测试网步骤仍需保持显式 opt-in 并继续贯通。
   - 2026-11-27：为 Rust CLI `quickstart` 增加版本化 `[QuickstartResult]` 机器结果合同（schema v1），返回 profile、运行/报告/证据包路径、运行身份和证据校验状态；Python wheel 改用该合同接收 CCXT 与 Paper 结果，不再从人类日志行摘路径/字段。CLI/Python 合同用例与跨入口验证已纳入本轮；此项收敛首跑集成边界，不表示数据下载入口或 Web Console 已完成。
   - 2026-11-27：Web Console 将教学 BarFrame 随静态资源包发布，页面从当前同版本 Console 下载，不再依赖写死的 v0.4.1 GitHub 原始链接；静态包校验样例字节与 `deploy/qianxing.bar-frame.example.json` 完全一致。仍需使用者将文件放入 `QX_API_DATA_ROOT`（或默认 `.qianxing/api-data`）；它是合成教学数据，Console 不会自动下载真实行情或隐式创建文件。
   - 2026-11-28：同源 Web Console 增加显式教学首跑，一键串联固定样例安装、现有数据校验、共享 Bar 回测和四份产物复核。安装复用服务端会话、CSRF 双提交和 Origin/Host 校验；同字节重复安装幂等，已有不同内容或非普通文件则拒绝且不覆盖。首跑要求现有规格指向 `sample.json`，沿用用户选择的策略及参数，不改写回测规格；静态 Console 保留手工下载路径。该操作不联网，真实行情下载入口仍未完成。
2. 策略模板先覆盖 SMA/EMA 趋势、RSI 均值回归、MACD、布林带、突破、定投/网格研究策略；模板必须声明适用市场、参数范围、费用/滑点假设、风险边界及禁止实盘的条件。
3. 增加批量参数扫描、滚动/样本外验证和同配置对比；报告显示交易次数、年化/累计收益、最大回撤、波动、Sharpe、胜率、盈亏比、手续费/资金费率、基准和数据覆盖区间，并写明空值/年化口径。
4. 用真实端到端工作负载定性能目标：半年 15 分钟 K 线、多标的、指标预热、撮合、账本、报告、冷启动和内存；固定源码哈希、CPU/OS、数据哈希和运行命令。每次优化都比较结果哈希或解释预期差异。

### P2：可视化与运维体验

1. 交互式权益/回撤/基准曲线、K 线成交标记、持仓和资金时间线、订单生命周期瀑布、策略日志定位到 bar 与 signal；筛选时间段、标的和策略。
2. 报告统一导出 HTML、JSON、CSV、XLSX 和可复现 EvidenceBundle；离线文件不依赖外部 CDN，运行数据与可分享报告分离。
3. 提供账户/策略总览：数据延迟、worker 心跳、连接状态、未完成订单、风险拒单、撤单/改单待对账、资金和保证金；告警需链接到具体订单、事件和处理建议。
4. 增加结构化日志关联 ID、API/worker 健康探针、重启/故障注入验收与排障文档；敏感配置只从环境/密钥管理读取。

### P3：发布门禁

1. Linux、Windows、macOS 的干净环境安装与卸载；Rust CLI 与 Python wheel 的 ABI、依赖、SBOM/许可证、签名和 provenance 检查。
2. CI 覆盖 Rust/Python/C++ SDK、Linux/PostgreSQL、Windows 长路径、CLI 首跑、报告产物、兼容性与性能回归；外部凭据测试明确标为未运行时，不得算通过。
3. 每个交易所独立保留经授权的 sandbox 往返证据；生产权限、风险限额、行情许可、供应商规格/签名复核与版本签名由发布责任人完成后再打 tag。

## 当前可确认的基线

- 本地能力和未收口项以 [V13 审计记录](自研量化框架审计与重构方案-V13.md) 及能力登记为准。已记录的近期证据包括离线 A 股/crypto quickstart、报告多格式输出、CCXT 订单路径和单条 Binance 公共行情 metrics scrape；这些证据不能替代全部 worker 的端到端 profile 或授权交易所验收。
- v0.4.2 正式版的 Rust CLI 首跑已扩展为六步链：自动生成 EvidenceBundle，并在结束前离线校验其工件摘要、RunManifest 身份和输入数据指纹；默认不重跑策略，`--html` 仅增加可视化工件。此改动收窄了“首跑回测结果如何交付/复核”的体验差距，不改变交易能力验收等级。发布后发现的 GitHub Release/PyPI wheel 字节差异及修复门禁见[发布范围与证据](release-scope-0.4.2.md)。
- Bitget UTA OCO 触发子单和零成交拒绝现在具备代码级恢复闭环；本地 qx-service 122 项、Python worker 28 项、架构快检 373 项通过。双腿同时成交时现能入账并报告、继续保持人工对账围栏，但不会自动净额处置；策略子单的 7 天查询窗口恢复、跨重启验证和真实 sandbox 往返仍未完成，因此能力仍为 `implemented-unverified`。
- 2026-11-28：Bitget UTA OCO 双腿均出现非零成交时，对账继续同步两条腿的精确成交、费用与远端身份；持久化组状态必须仍为 `ReconcileRequired`，并新增 `native_order_group_dual_execution` 报告问题项，引导人工核实最终净头寸。此代码级防误判不替代超出 7 天子单窗口的恢复，也不构成真实 sandbox 验收。
- 2026-11-28：当 Bitget 报告 OCO 已触发但未返回子单时，报告新增 `native_order_group_child_identity_unavailable`，保留人工对账围栏并给出核验 EventLog/交易所历史、禁止猜测与自动重发的处理建议。安全恢复边界依据[Bitget 策略子单查询说明](https://www.bitget.com/legacy-docs/uta/strategy/Get-Strategy-Sub-Orders)；普通[历史订单字段](https://www.bitget.com/legacy-docs/uta/trade/Get-Order-History)没有列出父策略单身份，这是按文档响应字段作出的限制判断，仍需供应商协议确认。
- 2026-11-14：CCXT OHLCV 限流重试计数与 RPC 耗时 histogram 已从 Python/Rust worker 接入 Prometheus：`qx_ccxt_ohlcv_rate_limit_retries_total{worker,account}` 和 `qx_ccxt_ohlcv_request_duration_seconds_{bucket,sum,count}`，标签不含 instrument；耗时覆盖成功及失败的已完成请求、包括限流退避，可在 Prometheus 侧计算分位数。后续核对发现计时点误包住 ticker 请求，已修正为只统计 OHLCV RPC。API `/metrics` 新增可运行任务与未确认控制命令的队列深度/最老等待年龄，并以 `*_metrics_available` 区分存储读取失败和空队列；订单组状态与 reconciler 最新报告问题数此前已由 API `/metrics` 暴露。执行提交/撤单/改单操作和 Binance/CCXT 完整对账轮次现发布 `qx_gateway_port_operation_duration_seconds_{bucket,sum,count}`，并通过 `qx_gateway_port_errors_total{port,class}` 输出固定错误类别；未知或非白名单类别统一归入 `unknown`，不导出原始错误文本。队列年龄、API scrape 接线、执行耗时、错误类别脱敏用例各 1/1，`cargo check --tests`、格式检查通过。远端 Linux CI 与真实公开行情 quickstart 尚未完成，因此 P0-4 和发布门禁仍保持进行中。
- 不承诺无定义边界的“全面超越”。对标以可复现性能、首次成功耗时、核心链路通过率、状态恢复率、报告交互功能和线上可观测覆盖率逐项验收。
