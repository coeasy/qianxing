# 策略未来数据与预热偏差诊断

`qianxing-strategy-diagnose` 使用现有版本化 `StrategyInput` JSONL 协议检查 Python 策略或兼容 JSONL 的外部策略 worker（包括 C++ 示例 worker）的两个风险面：

- **未来数据敏感性**：逐个决策时点重算策略，每个时点运行四种确定性反事实：混合 OHLCV 扰动、未来价格整体上移、整体下移、未来成交量归零。若任一输出的仓位目标、置信度、优先级、订单意图、信号 ID、失效时间、中间态字段或中间态可用性改变，报告 `potential_lookahead_detected`，并列明扰动类型和变化字段。
- **预热长度敏感性**：先排除时间戳大于或等于每个历史决策时点的 Bar，再用多个可见历史窗口重算；除最终决策外，还会在有界抽样的历史决策轨迹上比较目标仓位、置信度、优先级、订单意图及策略导出的中间态。这样可以发现早期分歧后来收敛的情况。报告 `trajectory` 覆盖率、是否抽样、首次分歧时点和变化字段。若结果未变但参考窗口不足或重放预算不足，会报告不充分状态，不把未检查区间说成稳定。
- **策略中间态敏感性**：Python 策略可选声明 `diagnostic_state(request)`，返回由指标名到 JSON 值组成的字典，例如 `{"rsi.value": 4821, "trend.fast_ema_raw": 102500}`。诊断 worker 会在每个因果/扰动调用中执行该钩子，报告逐指标变化；即使最终决策未改变，只要中间态改变也会标记潜在未来数据依赖或预热敏感。未声明钩子时报告 `intermediate_state_available: false`，不把缺少观测伪装成稳定。
- **PIT 可见性与修订偏差**：可选传入版本化事实账本，按每个历史 Bar 决策时点核对事实的 `effective_at`、版本 `available_at` 和 `value_fingerprint`。最终数据在当时尚不可用或后来被改成不同值时分别报告 `future_value_unavailable` / `revised_value_after_decision`；缺少可用时间则单列 `availability_unknown`，绝不折成通过。此合同适用于 A 股公告/公司行为、财报及供应商修订行情等带版本历史的数据。

示例：

```powershell
qianxing-strategy-diagnose `
  --input python/examples/strategy-diagnostics-input.json `
  --strategy python/examples/backtest_momentum.py `
  --pit-ledger python/examples/strategy-pit-ledger.json `
  --startup-windows 1,3,5 `
  --out target/strategy-diagnostics.json
```

在仓库源码环境中，也可以从仓库根目录执行：

```powershell
$env:PYTHONPATH = 'python'
python -m qianxing_strategy.diagnostics `
  --input python/examples/strategy-diagnostics-input.json `
  --strategy python/examples/backtest_momentum.py `
  --pit-ledger python/examples/strategy-pit-ledger.json `
  --startup-windows 1,3,5
```

## 从供应商快照导入 PIT 账本

`tools/import_provider_revision_ledger.py` 可把同一来源、同一标的的多个 Qianxing BarFrame JSON 快照转换为上述 `strategy-pit-ledger-v1`。每个快照都要显式配对 `--observed-at-ms`（UTC Unix 毫秒）；工具按时间戳和 OHLCV 字段生成稳定事实 ID，以快照 SHA-256 绑定每个观察版本，并只在规范化字段值改变时追加版本。它拒绝来源/标的漂移、错位字段、非递增时间、未来 Bar 时间戳及超出 i128/事实/版本预算的输入。默认不覆盖账本文件。

可重复传入 `--actions-snapshot` 与一一配对的 `--actions-observed-at-ms` 导入 A 股 `schema_version: 1` 公司行为信封（顶层 `source`、`instrument`、`actions`）。事件按 `ex_date` 的上海本地日界线作为 `effective_at`，按采集时刻记录版本可用时间；事件中的 `published_at` 会进入原始版本指纹，但不会被当作已验证发布时间。优先提供跨快照稳定的 `action_id`；若稳定 ID 对应的除权日或事件类型变化，导入会拒绝，因为 PIT v1 不能给事实的生效时间/字段元数据版本化。没有稳定 ID 时，以来源、标的、除权日、事件类型和登记日组成身份；未出现某事件不表示供应商撤回，因此不会推断删除。公司行为快照必须与 Bar 标的一致，每份也需要自己的首次采集时间。为跨快照关联事件，导入器额外接受可选的 `action_id` 采集注记；它不是 A 股执行器的 v1 字段，带该注记的输入不能原样传给回测执行器。

可选的 `--price-adjustment-basis` 记录供应商快照 OHLC 的复权口径：`raw`、`forward_adjusted`、`backward_adjusted` 或默认 `unknown`。只有在来源文档/响应元数据确认口径后才应显式声明。诊断会将同标的 `bar.open/high/low/close`（含 `_raw` 字段）的实值修订，与价格 Bar 生效时间之后、该次价格修订可用时间之前生效的 `corporate_action.*` 事实做有界关联。它报告修订覆盖的历史决策点、公司行为前的决策点、公司行为当时的可见性及最多 25 条样本；当声明后复权、公司行为在价格修订时已知而在部分除权前决策时尚不可见时，标为“可能后复权前视”。这是时间关系风险提示，不证明价格变化由该公司行为造成，也不代替供应商可信发布时间、除权价计算规则或逐日复权因子验证。缺公司行为历史、价格修订历史或口径仍未知会分别报告，不能当作安全通过。

```powershell
python tools/import_provider_revision_ledger.py `
  --snapshot maturity/evidence/provider-capture/snapshot-1.json `
  --observed-at-ms 1792710280759 `
  --snapshot maturity/evidence/provider-capture/snapshot-2.json `
  --observed-at-ms 1792710285104 `
  --actions-snapshot maturity/evidence/provider-capture/actions-1.json `
  --actions-observed-at-ms 1792710280759 `
  --actions-snapshot maturity/evidence/provider-capture/actions-2.json `
  --actions-observed-at-ms 1792710285104 `
  --price-adjustment-basis unknown `
  --output target/provider-pit-ledger.json
```

**时间语义必须保守解释：**导入的 `available_at` 是牵星首次采集到该值的时间，不是交易所最初发布时间。较晚的采集时间可以证明值在该次捕获时已存在，却不能证明它在此之前不存在；基于它进行 PIT 检查可能对早期决策报出偏差风险。工具不推断缺失 Bar 是供应商删除，亦不把重复的相同值伪造成修订。若要证明历史决策时供应商是否已发布某版数据，仍须提供带可信发布时间或可审计历史归档的来源记录。

2026-10-23 实测：用匿名 Binance Spot Testnet CCXT 获取两份相隔 4.3 秒的 15 根闭合 1 分钟 Bar 快照，Release CLI 输出均为同一数据 SHA-256；导入器生成 75 条 PIT 事实并通过诊断模块账本校验，未观察到字段修订。原始快照、捕获时间、账本和导入结果保存在 `maturity/evidence/binance-testnet-pit-import-2026-10-23/`。这证明真实供应商 BarFrame 能被导入和复核，不证明已捕获供应商修订、确切发布时间或私有交易链路。无 `--force` 写入通过同目录原子硬链接发布，目标已存在时即使发生并发也不会覆盖；目标文件系统不支持硬链接时会安全报错。

诊断文件可绑定到同一策略、同一数据输入的单次 Bar 回测研究报告：

```powershell
qx-cli report target/runs/<run>.v7.summary.json `
  --html --json `
  --strategy-diagnostics target/strategy-diagnostics.json `
  --output target/research-with-diagnostics.html
```

报告入口先复核摘要声明的输入，再要求诊断文件的 `strategy_id`、`instrument` 和 `data_fingerprint` 与复核结果一致。HTML 中的诊断区可按决策时点、字段和事实筛选；JSON 报告保留完整诊断对象；XLSX 附带诊断摘要和分段 JSON 证据，字符串按 Excel 单元格长度切片且可按诊断编号/分段序号还原。Web Console 也可在选中已复核 Bar 运行后上传本地诊断 JSON，API 重新复核回测产物并核对同一组身份字段，再将诊断作为“客户端计算、服务端未重算”的附加结果返回。Web 诊断摘要使用 PIT 报告实际提供的按事实数和事实—决策时点数两套计数，并展示账本来源、指纹及采样覆盖；单独的 PIT 明细表可按事实、实体、字段和时间筛选，逐行展开版本发布时间与完整样本。单次 HTML/JSON/XLSX、共享账户多市场 Bar Web/API 均可附加身份绑定诊断；多腿 Web/API 报告支持按腿提交单份或两腿诊断批次，并分别核对共享策略身份和各自 BarFrame 指纹。多账户 Bar/深度批次可按 account_id 接收并绑定最多 32 个成功账户的诊断集合；多市场深度报告支持 HTML/JSON/XLSX 附件。单标的 Bar 和多市场 Bar 的单次运行均可将诊断文件作为独立输入放入 EvidenceBundle；离线验证核对附件 SHA-256 及策略、标的、数据指纹，便携导出会复制附件。该验证不重算客户端诊断算法。多市场深度、多账户 EvidenceBundle 与多轮 `--against` 仍不接收外部诊断附件。

普通单标的 Bar 的诊断证据包可按以下方式生成、验证和便携导出：

```powershell
qx-cli report target/runs/<run>.v7.summary.json `
  --json --evidence `
  --strategy-diagnostics target/strategy-diagnostics.json

qx-cli evidence verify-run target/runs/<run>.strategy-diagnostics.evidence.json

qx-cli evidence export-run target/runs/<run>.strategy-diagnostics.evidence.json `
  --output-dir target/portable-diagnostic-evidence

qx-cli evidence verify-run target/portable-diagnostic-evidence/evidence.json
```

## 从多市场深度运行自动生成内置策略预热诊断

多市场深度回测完成后，可让 CLI 复验运行产物、RunManifest、各市场 DepthFrame 和质量清单，并用产物中的策略配置重新生成 Rust 内置策略诊断：

```powershell
qx-cli strategy diagnose-depth target/runs/<run>.multi-market-depth.json `
  --output target/depth-strategy-diagnostics.json --html

qx-cli report target/runs/<run>.multi-market-depth.json `
  --strategy-diagnostics target/depth-strategy-diagnostics.json `
  --html --json   # 需要机读摘要时单独重用已生成的诊断 JSON
```

生成器只重放可从产物重建的 Rust 内置策略，盘口事件严格沿用深度回测的买一卖一中点和全档数量汇总转换规则，并将每个诊断绑定到对应策略槽、标的、数据指纹、快照数与最后输入时点。比较窗口基于策略配置的最大窗口，按 1×/2×/4× 生成并限制单窗口锚点不超过 250；历史轨迹每标的最多增加 96 次策略重放。包含外部策略或依赖动态持仓/购买力的 sizing 会拒绝自动生成，因为运行产物没有完整保存策略代码与每时点账户上下文。

## 从标准 Bar 回测自动生成 Rust 内置策略诊断

`qx-app` 产生的单标的 Bar 运行摘要可连同生成该次回测的 `BacktestSpec` 重新构建内置策略，并产出完整策略偏差诊断及交互式 HTML 报告：

```powershell
qx-cli strategy diagnose-bar target/runs/<run>.summary.json `
  --spec target/backtest-spec.json `
  --output target/strategy-diagnostics.json --html
```

生成前会核对摘要与规格中的运行/策略/标的身份、规范化规格 FNV 指纹、RunManifest、BarFrame 内容指纹/数量/起止时间，以及权益与成交产物的行数和末值。HTML 由现有离线报告渲染器生成，包含权益/成交/月度图、交互式研究曲线、事件追溯和未来数据/预热/PIT 诊断。报告不引入网络资源。

此自动重放只支持单策略、单标的的 Rust 内置策略；多策略组合、参考腿套利和动态账户 sizing 会失败关闭，因为摘要没有保存每时点策略账户上下文。单标的 Bar 输入上限为 65,536 根，诊断仍受未来扰动/预热重放预算约束；PIT 状态保持 `visibility_unknown`，需导入可信的供应商版本账本才能判断数据发布时间可见性。

Rust `Strategy::on_event` 一次只接收当前事件；深度内置策略诊断现会额外执行有界未来扰动：对至多 16 个采样的未来中点 Bar 同时平移 OHLC 并调整成交量，以新策略实例重放全序列，再核对被扰动事件之前所有已产生的决策与策略主动导出的诊断状态。每条检查会记录扰动类型、定点价格/成交量偏移、目标时间、被比较的历史点数和差异字段。每标的最多处理 65,536 个输入事件、最多 1,000,000 个重放事件，超过内存/计算边界时返回 `insufficient_work_budget`，不足两个事件返回 `insufficient_history`。`no_change_detected` 仅代表该次样本在受测 Rust 事件链中未观察到前缀变化，不能证明策略私有文件、网络/进程全局依赖或所有潜在未来数据路径不存在；检测到前缀差异时标为 `potential_lookahead_detected`，也应检查非确定性重放。运行产物仍不包含供应商版本事实账本，因此 PIT 状态为 `visibility_unknown`。Python/JSONL 策略仍可使用本文前述多种未来数据反事实诊断，并导入可审计的 PIT 修订账本。

## 从共享账户多市场 Bar 运行自动生成策略诊断

多市场 Bar 回测产物可一次为所有 Rust 内置策略槽生成未来扰动、预热轨迹和 PIT 边界诊断，并直接接入离线交互报告：

```powershell
qx-cli strategy diagnose-multi-bar target/runs/<run>.multi-market.json `
  --output target/multi-market-strategy-diagnostics.json --html
```

命令先重验每个 BarFrame 内容指纹、可选 DatasetManifestV2、组合数据指纹、RunManifest、事件流摘要、ReplayVerifier 账本、权益与成交产物，然后从已落盘 spec 重建每个策略槽。输出按 `strategy_id` 与标的绑定，报告显示每个槽自己的未来扰动状态、1×/2×/4×预热窗口和历史轨迹。数据发布时间/修订账本不在回测产物中，PIT 一律显示 `visibility_unknown`。

生成器拒绝外部策略和动态 sizing，因为产物不含可重建的策略代码或逐时点共享账户持仓/购买力。每个策略输入最多 65,536 根 Bar，最多 512 个策略槽，所有策略槽累计最多 1,000,000 个策略 Bar 事件；未来扰动和预热轨迹各自使用策略槽均分的有界工作预算。固定上下文采用每个策略声明的 reserved capital、空持仓，并在报告中注明此假设；它是偏差诊断的重放环境，不是逐时点的生产账户状态复刻。诊断 JSON 上限为 1 MiB，输出路径不得覆盖运行产物、源 Bar、质量清单、RunManifest 或同次生成的 HTML 报告。

`--html` 由同一离线报告出口重新复核并渲染诊断，不需要网络资源。完整诊断数组也可通过 `report --strategy-diagnostics` 单独重用，并继续走 JSON/XLSX/EvidenceBundle 身份绑定流程。`no_change_detected` 仅代表有限扰动样本中，当前 Rust 策略事件链的历史前缀没有变化；它不能证明策略通过私有状态、网络或进程全局读取未来数据的路径不存在。

## 从多账户 Bar 批次自动生成逐账户诊断

多账户每个成功运行都可以从已保存的输入规格和运行摘要重建内置 Rust 策略，并一次生成完整诊断附件及交互式报告：

```powershell
qx-cli strategy diagnose-multi-account target/multi-account-result.json `
  --spec target/multi-account-spec.json `
  --output target/multi-account-diagnostics.json --html
```

生成前会核对 batch/spec 指纹、账户集合与批次汇总；随后为每个成功账户分别复核 BacktestSpec、RunManifest、BarFrame 内容指纹、权益和成交产物，再运行未来 Bar 扰动、1×/2×/4×预热窗口及历史轨迹诊断。失败账户不生成诊断，但附件必须覆盖每个成功账户。所有账户身份分别保留，报告会重验诊断中的策略 ID、标的和数据指纹。

为控制累计重放，单批最多 32 个账户、成功账户合计不超过 262,144 根 Bar，最终诊断 JSON 不超过 1 MiB。外部策略、组合策略、参考腿及动态账户 sizing 仍失败关闭；需要逐时点账户状态的策略上下文不能从批次汇总可靠重建。`--html` 将诊断交给多账户离线报告复核器，显示权益曲线、逐账户成交/事件及可搜索的诊断证据。`report --xlsx` 也可导出 Overview、Accounts、Equity、Fills、Events、StrategyDiagnostics 和 DiagnosticEvidence 工作表。

为每个成功账户生成独立运行证据包，并携带账户专属诊断快照：

```powershell
qx-cli report target/multi-account-result.json --json --html `
  --strategy-diagnostics target/multi-account-diagnostics.json --evidence
```

报告 `accounts[]` 的 `run_evidence_path` 指向该账户标准 Run EvidenceBundle。诊断快照按账户稳定命名且不覆盖不同内容；`evidence export-run <run_evidence_path> --output-dir <dir>` 会将快照一并复制，`evidence verify-run <dir>/evidence.json` 会核 SHA-256 并重验策略 ID、标的和数据集内容指纹。多账户回测输出现落盘 RunRecord，并在 summary 中登记撮合内核、账户本金、风控来源和费用来源，使证据包能够校验摘要/权益/成交/RunManifest。Rust Bar 诊断附件的 `data_fingerprint` 统一采用数据集内容指纹；RunManifest 的 `barframe:` 合成前缀仍独立核验。

该入口生成的是逐账户标准证据包，不是一个聚合整个批次、规格与所有账户包的单一便携包。外部策略、组合策略、参考腿及动态账户 sizing 的诊断上下文限制仍在。

针对性行为用例：

```powershell
python -m unittest python.tests.test_strategy_diagnostics -v
```

诊断工具为每次策略调用启动独立 worker，避免模块全局状态在反事实运行之间串扰；默认最多检查 200 个未来数据决策点，最多允许 1000 个，每个决策点分别计入四个扰动检查。预热轨迹把同一 `max_checks` 预算平均分配给各窗口，按时间均匀抽样并复用已计算的最终时点，worker 重放总数不超过该预算。只有可提供最长参考窗口完整历史的时点才计为可比点；报告分别给出 `decision_points_checked`、`decision_points_eligible`、`decision_points_available`、`decision_points_excluded_insufficient_reference_history` 和 `decision_points_sampled`。历史不足的时点不会用相同前缀冒充不同预热窗口的对比；没有可比点时返回 `insufficient_reference_history`。报告逐条保留预算内所有出现决策或已导出中间态差异的时间点，`first_divergence` 仍作为首条兼容摘要。单次 worker 默认 10 秒超时、硬上限 120 秒。PIT 账本使用 [strategy-pit-ledger-v1 schema](../schemas/strategy-pit-ledger-v1.json)，必需包含事实生效时间、每个版本的修订编号和值指纹；值指纹只用于版本间相等性比较，导入方需从规范化值稳定生成，工具不据此验证供应商原始值。`available_at: null` 表示供应商无法提供可用时间，诊断将结果标为未知。事实/时间点组合超过 500 万时拒绝运行，防止意外的超大输入拖住 worker。`diagnostic_state` 只在显式诊断模式调用，不进入回测策略输出协议，也不会写入普通交易产物。输入中的完整 Bar 序列供未来扰动分析使用；每个历史决策点只使用时间戳严格早于该点的 Bar。报告明确给出 `visible_bars`、`excluded_future_bars`、`reference_available_bars`、`reference_history_complete` 以及轨迹首次分歧和全部已观测分歧。

**解释边界：**发现扰动改变决策或中间态，是策略可能依赖未来数据的证据；未发现变化不能证明所有未来数据路径都不存在。PIT 检查只能覆盖导入账本列出的事实与版本；它不验证供应商声称的发布时间，也不会自动修复回测数据，必须把供应商版本历史或可审计的导入记录导出到账本。中间态仅覆盖策略作者主动导出的 `diagnostic_state`；Python worker 可在显式诊断模式下调用钩子，外部 JSONL worker 可在成功响应顶层附加同名对象（字符串键到 JSON 值），未附加时仍只比较最终决策。若仅一侧导出中间态，变化字段包含 `__availability__`，防止条件导出造成漏报。工具不会自动读取进程内部状态。预热窗口结果仅说明本次输入与列出的窗口。Rust 原生策略按事件逐条接收因果行情，接口层不会把未来 Bar 暴露给策略；Rust SDK 现可在有界预算内对齐多个历史事件时点比较不同窗口的决策及可选中间态，但不会自动观察未导出的私有指标。C ABI 插件没有批量未来反事实入口。Web/API 只接收用户本地预先计算的 JSON 并绑定回测身份，不在服务端执行策略代码或重跑诊断。牵星回测引擎本身对 Bar 策略只传入当前决策 Bar 之前的历史，因此 Python/外部 worker 工具补充检查完整序列研究环境下的行为，不取代引擎的因果性边界。

外部 worker 使用 `--worker-executable <path>`，并可重复传入 `--worker-arg <arg>`。例如 C++ JSONL worker：

```powershell
qianxing-strategy-diagnose `
  --input python/examples/strategy-diagnostics-input.json `
  --worker-executable build/cpp/qianxing_jsonl_strategy `
  --startup-windows 20,50,100
```

worker 必须从 stdin 读取一行版 `StrategyInput` JSON 并输出一行 `{"ok":true,"output":{"target_qty":0,"confidence":0,"priority":0,"intents":[]}}`。若要比较内部指标，可在成功响应顶层附加 `diagnostic_state` 对象，例如 `{"ok":true,"output":{"target_qty":0,"confidence":0,"priority":0,"intents":[]},"diagnostic_state":{"ema.fast_raw":102500}}`；中间态必须是可 JSON 序列化的对象。诊断对每次反事实启动一个独立 worker，不会把命令行参数写入报告。

Rust 原生策略与受信任 C ABI adapter 可通过 `qx_sdk::diagnose_startup_windows` 做终点决策预热敏感性检查；新增 `qx_sdk::diagnose_startup_trajectory` 会在多个历史事件时点重放并比较各窗口，`max_replays` 将额外策略调用限制在 1..=1000，最终时点复用终点比较结果。轨迹结果包含检查点覆盖数、是否抽样、首次分歧和预算内全部分歧时间点及变化字段。调用方传入严格递增的 `MarketEvent` 历史、窗口长度、每次返回全新策略实例的 factory 和 `StrategyContext`；诊断会从每个窗口对应的历史后缀重新初始化并重放，比较 `confidence`、`priority`、`intents` 和可选导出的中间态。Rust 策略可实现 `Strategy::diagnostic_state()` 导出确定性的只读 JSON 对象；`diagnose_startup_windows` 与轨迹入口都会逐字段和最大窗口比较，即使决策相同也能标记预热状态差异。内置 `SmaCrossStrategy` 导出窗口 closes 与信号计数作为示例。未实现钩子的 Rust 策略和未导出 `qx_strategy_diagnostic_state` 的 C ABI 动态库仍只比较决策；动态 C ABI 可选导出该符号，将不超过 64 KiB 的 UTF-8 JSON 写入宿主提供的缓冲区，Rust 只在显式诊断时读取并按 JSON 逐字段比较。该可选符号不改变现有 vtable ABI，旧插件可继续加载。该入口不执行未来 Bar 扰动；Rust `Strategy` 事件 API 每次只收到一个当前事件，未来数据不会被接口传给策略。动态库的可选符号和 C++ 样例由 `cpp_plugin_host` 集成用例验证；该用例需要具备 C++ 编译器的 SDK CI 环境运行。
