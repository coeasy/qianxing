更新时间：2026-09-11

本文是当前代码状态的验收记录，区分“代码已经形成可运行闭环”和“仍需真实环境或产品化工程才能宣称完成”。方案文档中的设计描述不能替代本清单中的测试证据。

## 2. 已完成的工程化约束

API 已提供受权限保护的 Prometheus /metrics，输出请求、限流拒绝和认证拒绝计数；LiveEventPipeline 指标提供摄取、去重、重试、刷新和失败计数的 Prometheus 文本序列化；Relay/Consumer worker 通过 `storage.data_dir/worker-metrics/*.prom` 原子写入心跳、批次、失败和 DLQ 指标，API 会在 `/metrics` 中聚合这些跨进程样本；`/health` 作为存活探针，`/ready` 会检查控制面、已声明研究快照、生产凭据/冻结规格文件和已有 worker 指标中的 down/stale 状态，并在依赖不可用时返回 503。

- 策略不能直接访问交易所凭证、Venue client、Ledger 或控制面。
- `StrategyDecision.intents[]` 在进入 Risk/OMS 前校验身份、版本、有效期、重复 `intent_id`、标的、数量和价格。
- Python worker 为持久进程；超时、断管道、非法 JSON 和标准错误尾部均进入错误诊断。
- 外部策略子进程使用最小环境白名单，不继承交易进程环境；敏感凭证变量会在配置校验和进程启动前双重拒绝。
- 生产独立 Rust/C++ 策略进程必须配置 `strategy_artifact_sha256`；配置后 host 在 spawn 前校验可执行文件，Python `.py` 文件也可复用同一校验。
- CCXT Worker 同样使用按配置声明的最小环境白名单，只传递 `credential_env` 指定变量和 Python 运行基础变量。
- CCXT Rust 进程桥接已具备配置化响应超时；超时/退出统一进入未知结果边界，禁止自动补单。
- C ABI 插件返回的决策会在调用插件释放函数前复制并校验，定点数使用稳定的 `i128` C 表示。
- C ABI verified loader 已增加 detached Ed25519 动态库签名校验单测；公钥信任根、轮换、沙箱和回滚策略仍由部署系统提供。
- RuntimeConfig 已支持排除自身字段的稳定 `config_fingerprint`；生产示例已锁定配置指纹，配置被修改后 API/worker 启动会拒绝加载。
- Bar/Tick/订单簿回测严格校验时间和来源序列，禁止把当前市场事件当成已知输入。
- 分段 EventLog 的完整段不可变，尾段只允许追加，manifest 校验事件数、序号和摘要。
- 运行时仍保留 `target_qty` 兼容模式，旧策略不会被无提示地改写语义。
- `LiveEventPipeline::metrics()` 提供摄取、去重、瞬态重试、刷新和失败计数；指标与 staging clone 共享但不写入交易事实。
- `qx-cli` Relay/Consumer worker 已提供原子指标文件、worker 心跳和处理结果计数；API `/metrics` 已覆盖跨进程聚合，并按 `messaging.worker_stale_after_ms` 将失联 worker 暴露为 `qx_worker_up=0`；Prometheus 告警模板已放入 `deploy/prometheus/qianxing-alerts.yml`，OTel trace 仍待补齐。

## 3. 不能宣称“全部完成”的部分

### 3.1 多语言高性能数据面

受信任 C ABI 动态库现已接入 qx-cli 的 strategy-backtest 和 Strategy worker：加载前执行文件大小、SHA-256 白名单和可选 Ed25519 校验，回测使用 Bar 事件，运行时 Job 使用 Timer 事件，输出继续经过统一 StrategyContract、Risk 和 OMS；production 配置已强制 C ABI 同时提供 Ed25519 公钥和签名。C ABI 仍不提供不受信任原生代码沙箱。

目前生产可用的跨进程策略边界包括版本化 JSONL、`framed_json`（QXSF 固定头、序号、长度上限、CRC32）、Python/C++ Worker 的 `shared_memory_json`，以及 Python/C++ Worker 的 `shared_memory_columnar`（QXCB 固定宽度 Bar 列）；均使用双向 SPSC mmap ring，并已覆盖 Bar 回测验收。QXCB 当前是列式定点传输，不等同于 Arrow C Data Interface 零拷贝行情热路径；`cargo run --release -p qx-strategy --example ring_bench` 已提供传输层 P50/P95/P99/P999/吞吐微基准，但完整策略端到端基准仍需建立。

### 3.2 C++ 原生插件产品化

C ABI、Rust Host 绑定、动态库加载、CMake 示例、决策内存所有权规则、动态库大小限制、SHA-256 白名单和可选 detached Ed25519 二进制签名校验已经具备；但跨平台预编译 SDK、签名信任根/证书轮换、ABI 白名单、沙箱、崩溃隔离和版本回滚仍未完成。当前不应把不受信任的 C++ 插件直接加载进交易进程。

### 3.3 订单簿和衍生品回测深度

通用 Bar 回测已经支持产品规格、合约乘数、线性/反向 PnL、杠杆、保证金、资金费、利息、交割和强平事件。`TickBacktestEngine`/`OrderBookBacktestEngine` 已支持注入产品规格、显式杠杆策略、衍生品成交 Ledger 语义，以及可复现的快照延迟/队列前置量/固定冲击模型；交易所真实 L3 队列、撤单竞态、逐事件冲击校准和完整强平过程仍未全部纳入。

### 3.4 公共 CCXT 真实环境

公共 CCXT REST 主链路、订单执行、行情轮询、对账、持仓、资金费率和资金流水事实边界已经接通；真实 Binance 公共 CCXT 现货与永续 `fetch_ticker` 均已通过，永续 ticker 缺少 bid/ask 时会回退到订单簿首档，且 `credential_env: null` 的匿名公共配置已修复并通过验证。CCXT Pro 断线重连、不同交易所账单字段/精度/杠杆档位矩阵、沙盒和实盘凭证仍需真实环境验收。现阶段不能以本地 Mock 测试替代交易所验收。

### 3.5 生产基础设施

当前文件/SQLite 是单机可恢复实现；`qx-storage` 已提供可选 PostgreSQL TLS 连接、幂等迁移和可配置单进程连接池，覆盖控制面、控制命令队列、JobQueue、审计链、快照、EventLog、Outbox 以及消费者位点/死信状态，`qx-cli --features postgres` 可以按运行时配置装配既有运行端口。PostgreSQL 的读写分离、跨节点 leader/fencing 编排、ClickHouse/Parquet 数据湖、真实 NATS/Redpanda 集群验收、秘密管理、证书签发、Tracing/告警和完整灾备演练仍是后续生产化工作；Relay/Consumer worker 已具备运行时配置入口和基础 Prometheus 指标聚合。

### 3.7 Outbox/MQ 事件投递

文件、SQLite、PostgreSQL 均已实现 `OutboxStore`，并提供通用 `OutboxRelay`；可选 `qx-storage/nats` 已接入 NATS JetStream Publisher 和 Pull Consumer，文件/SQLite/PostgreSQL 均提供消费者 checkpoint、event_id 幂等、重试和死信状态。`qx-cli outbox-relay` 可执行单批投递，`outbox-relay-worker` 可按运行时配置持续投递，`event-consumer-worker` 可持续拉取并调用外部 JSON handler，`consumer-dlq-replay` 可发布带确定性 replay event_id 的死信重放。事件幂等追加、过期租约接管、fencing token、claim→publish→ack、失败重试和确认删除均有契约测试；consumer contract 已覆盖 Applied、Duplicate、Retried、DeadLettered；`ConsumerEngine::consume_with_projection` 和 NATS 对应入口已提供 projection + processed marker + checkpoint 原子提交；worker 心跳、处理计数、发布失败和 DLQ 计数已接入 API `/metrics`，失联窗口会将 worker 暴露为 down，Prometheus 告警模板已提供。PostgreSQL EventLog 已支持 EventLog/Outbox 同一事务提交；文件/分段后端仍是顺序写入并依靠恢复扫描补齐。当前缺口是 stream/consumer 自动治理、真实集群故障矩阵、跨服务重放、领域 reducer 表与 projection 的事务适配、告警送达/SLO 和 trace；因此目前是“MQ 发布、Relay/Consumer worker、基础指标与 DLQ 重放入口已落地”，不是“MQ 全生产链路已完成”。

### 3.6 研究产物治理

`StrategyResearchSnapshot` 已能携带 CandidateBinding、FeatureArtifact、FactorReport、PIT 时间和数据指纹；production 中已绑定交易对象的策略已强制声明 `research_snapshot_required`、`research_snapshot_path` 和 `research_data_fingerprint`，运行时会拒绝指纹不一致或未通过事件回测验证的快照；兼容的裸 `target_qty` 路径仅保留给回测/纸面渐进迁移。

## 4. 后续实施顺序

1. **P0：验收与安全边界**。增加 Rust/Python/C++ 等价输入输出向量、非法插件输出、崩溃/超时/重复提交和未知订单状态故障矩阵；完成 C++ 插件签名、沙箱和动态加载宿主。
2. **P1：订单簿真实性**。把产品规格和衍生品保证金接入 Tick/L2 回测，增加队列位置、撮合延迟、撤单竞态、冲击模型和可重复撮合基准。
3. **P1：高性能数据面**。保留 JSONL 控制面，增加 Arrow/Shared Memory 数据面，并以同一 `StrategyDecision` 语义做回放一致性测试。
4. **P1：CCXT 生产验收**。逐交易所建立精度、合约、杠杆、账单、UserStream 重连和未知结果恢复矩阵；至少完成 Binance/OKX 两套沙盒证据。
5. **P2：基础设施**。在现有 PostgreSQL 连接池、Outbox Relay/Consumer worker 和 NATS 端口上增加读写分离、跨节点 leader/fencing、Redpanda 可替换适配、指标/Tracing/告警、密钥轮换与灾备恢复演练。
6. **P2：治理收口**。默认要求研究快照、策略包签名、RunManifest、回测/实盘配置锁定和可审计发布回滚。
